# NH 수입·입출금과 계좌 통보

## 연결 구조

`NH → 서버 WebSocket → 해당 계좌 REST 재조회 → DB 원자적 반영 → /ws/namuh → 화면 갱신`

서버의 기존 lifespan 작업이 브라우저 접속과 무관하게 연결 계좌를 관리한다.
앱키·토큰·통보 원문을 브라우저에 전달하지 않는다.

- 국내 주식·국내 주간선물: `d2`, `d3`
- 해외주식: `d0`, `d1`
- 금현물: `de`, `d3`
- 국내 야간선물: `dv`, `dn`
- 해외선물: `dk`, `dj`

통보는 모두 운영 7070 포트, `tr_key=""`로 등록한다. 기존 국내 시세와 한 소켓을 공유한다.
키별 국내 시세·통보 합계 30건, 해외 시세 소켓 30건으로 제한한다.
통보 자리를 먼저 확보하며 남은 국내 시세는 기존 KIS/조회 경로를 사용한다.
복수 키도 각 키의 연결 계좌 통보를 수신한다. 같은 키의 운영·모의가 함께 연결되면
운영 환경을 우선하며 나머지는 주기 조회한다.

공식 공개 명세에 배당·이자·입출금 전용 통보는 없다. 서버가 60초 주기로 재조회한다.
주문·체결 통보는 재조회 신호로만 사용하며, 통보의 수량·금액을 잔고에 직접 더하지 않는다.
연속 통보는 합쳐 처리하고 재접속 직후 및 통보 약 12초 뒤에도 재조회하여 반영 지연을 보완한다.
잔고 조회 실패 시 기존 기록·잔고를 보존한다. 거래내역만 실패하면 검증된 잔고는 갱신하고,
기존 거래내역과 마지막 성공 시각을 유지한다. 계좌 관리와 수입·입출금 화면에 보류 사유를 표시한다.

## 수입·입출금 원장

공통 `POST /common/inquiry/v1/totalTransaction`을 월 단위로 끝까지 조회한다.
화면에서 최대 1년 범위를 선택하여 추가로 가져올 수 있다. 모의투자는 이 API를 제공하지 않는다.

- 배당·분배금, 이자, 기타 수입, 원금 입출금, 계좌 내 이동, 매매·입출고, 비용, 확인 필요로 구분.
- 실제 원통화 예수금 전후 차이를 현금 증감액으로 사용한다. 세전·세금·수수료는 합계가 검산될 때만 표시한다.
- 원금과 이자가 섞인 RP 등은 명시적인 이자에서 세금을 뺀 금액만 수입으로 집계한다.
- 취소·정정·상환 등 불확실한 적요는 확인 필요로 남긴다. 사용자가 분류와 사유를 기록한다.
- 거래일·일련번호·통화·계좌 지문으로 중복을 막는다. 재조회는 사용자 사유를 보존한다.
- 증권사에서 같은 거래의 내용을 바꾸면 확인 필요로 전환하고 편집 버전을 올린다.
- 사유 변경은 이력을 남기며, 오래된 화면에서 저장한 요청은 충돌로 거절한다.
- 계좌번호·상대계좌·성명 등 종합거래내역의 개인 식별 원문은 이 원장에 저장하지 않는다.

## 배당 자동 반영 (배당 전용 경로)

종합거래내역에는 거래 일련번호가 없어 일반 수입·입출금 자동 반영은 계속 보류한다(아래 검증 경계).
배당만 2026-10-01 운영 탐사(실계좌 3개, 365일, 읽기 전용)에서 확인한 관계로 가져온다.

| 구분 | 원천 | 대상 행 | 키 |
|---|---|---|---|
| 국내 | 종합거래내역 | 적요 `배당금`·`분배금`, 통화 빈 값(=KRW), 6자리 종목 | 계좌 지문·처리일 `trd_dt`·적요·종목·같은 키 순번 |
| 해외 | `POST /gbstock/inquiry/v1/dailyTransaction` (입금 `01`, 외화주식 `00001`) | 적요 `외화배당금입금`, `외화제세금환급` | 계좌 지문·처리일 `trd_dt`·거래일련번호 `trd_sno` |

- 해외 일별거래내역의 `trd_sno`는 일자별 번호다. (`trd_dt`, `trd_sno`)가 96/96 유일했고 반복 조회·분류 필터 변경에도 같았다.
  해외 ETF 분배금도 외화주식 `외화배당금입금`으로 온다. 종합거래내역의 해외 배당 행은 가져오지 않는다(이중 반영 방지).
- 국내 키에 금액을 넣지 않는다. 같은 키의 금액·세금이 바뀌면 새 거래가 아니라 확인 필요와 버전 증가로 남는다.
  같은 날 같은 종목의 같은 적요가 둘 이상이면 응답 순서로 순번을 붙인다.
- 수취일은 실거래일 `ral_trd_dt`(처리일보다 늦으면 처리일)이고, 처리일은 `booked_date`로 보존한다.
  실거래일이 처리일보다 앞서는 소급 등록 행이 있어 자동 조회는 마지막 성공일부터 30일을 겹쳐 다시 읽는다.
- 최초 가져오기는 최근 365일이고 종합거래내역은 365일을 한 번(연속 조회 포함)에 읽는다(운영에서 3계좌 확인).
  이후 자동 재조회는 5분 간격으로 제한하고, 잔고는 계속 60초마다 갱신한다. 기간을 지정한 가져오기는 제한하지 않는다.
- 가져오기가 실패하면 `broker_activity_state.failed_attempts`·`attempted_at`을 남기고 자동 재조회를
  5분·10분·20분…(최대 1시간) 뒤로 미룬다. 성공하거나 기간 지정 가져오기가 성공하면 초기화한다.
- 응답이 비면(국내·해외 모두) Output 블록 없이 `rsp_cd` 13578만 온다. 0건으로 처리한다. 그 밖에 Output이 없으면 전체를 보류한다.
- 해외 종목코드 `티커 시장`(US/HK/JP/AU/DE)은 잔고 동기화와 같은 규칙으로 해석한다. 실패해도 원래 티커로 기록한다.
  배당 통화는 상장 통화와 다를 수 있어(홍콩 상장·CNY 지급) `cur_cd_nm`을 쓴다.

금액:

- 국내: 세전 `trd_amt`, 원천징수 `tax_sum`(15.4%), 세후 = 세전 − 세금. 바로 앞 행의 거래 후 예수금 차이로 검산하고
  결과를 `balance_check`(matched·mismatch·no_previous)로 남긴다. 세금이 세전 이상이거나 수수료가 있으면 확인 필요.
- 해외(원통화): 세후 `fc_trd_amt`(=외화 예수금 증감), 현지세 `fc_tax_sum`, 세전 = 세후 + 현지세.
  국내 추가 원천징수 `tax_sum`(원)은 원화 예수금에서 빠진다(원화 잔고가 음수가 될 수 있음).
- 해외(원화): 세전 = `krw_sas_amt`, 세후 = round(`fc_trd_amt` × 환율) − `tax_sum`. 이 값이 수익 분해의 배당 수입이다.
- 환율 `aly_xcg_rt`는 1통화단위당 원이다. 행마다 round(세전 × 환율)과 `krw_sas_amt`가 ±1원인지 검산하고,
  맞지 않으면 100단위 표기(/100)를 한 번만 시도한다. 그래도 맞지 않거나 환율·세금·예수금 관계가 맞지 않으면
  원통화 금액만 기록하고 확인 필요로 둔다(원화 수익에 넣지 않는다). JPY 등은 운영 자료가 없어 이 자가검증에 의존한다.
- `fc_amt`·`krw_amt`·`krw_trd_amt`·`fc_sas_amt`는 배당 행에서 0이거나 의미가 맞지 않아 사용하지 않는다.
- `외화제세금환급`은 새 배당이 아니다. 미국 원천세 15% 환급(외화 +)과 국내 15.4% 징수(원화 −)의 사후 정산이므로
  같은 종목 배당의 세금 조정(`adjustment: tax_refund`)으로 넣는다. 세전을 다시 더하지 않고 원화 순효과만 수입에 반영한다.

반영 계약: 배당은 기존 `broker_transactions` 원장에 들어가 수익 분해(`income_events`)에 수입으로 나타난다.
현금·잔고·NAV 입출금·좌수는 바꾸지 않는다(NH 현금은 이미 잔고 스냅샷에 있다).
조회 범위가 겹쳐도 같은 키는 다시 넣지 않고, 같은 키의 내용이 바뀌면 확인 필요로 전환한다.

### 미확인 태그

- 수동 배당 수취: 같은 계좌(수취에 계좌가 있을 때)·종목·통화, 수취일 ±5일(실거래일 또는 처리일),
  실수령액(원화 20원 또는 0.2%, 외화 최소단위 2 또는 0.2%)이 맞는 NH 배당이 있으면 `nh_confirmed`, 없으면 `unconfirmed`.
  해외는 국내 추가세를 외화로 환산해 뺀 세후액과 세전액도 대조한다. 한 NH 기록은 한 수취만 확인한다.
- 짝지어진 수동 수취가 있으면 그 NH 배당은 수익 분해·계좌 수입 합계에서 다시 집계하지 않는다(수취가 이미 분류함).
  짝짓기는 조회 시 일대일로만 하며 원장의 `income_krw`는 지우지 않는다(수취 하나가 NH 배당 여러 건을 지우지 않게).
- 계좌 수입 합계의 `amount`(원통화)와 `amount_krw`는 같은 배당 행의 합이고, 외화 세금 정산은 `adjustment_krw`로 따로 둔다.
- 배당 캘린더: 지난 지급일 일정(예상·배당락·기준일 제외)에 같은 종목의 NH 배당이 지급일 −3일~+10일 안에 있거나
  NH로 확인된 수동 수취가 그 일정에 연결돼 있으면 `NH 확인`, 아니면 `미확인`. NH 확인 일정은 수취 입력을 숨긴다.
  일정은 전 계좌 합산 보유 기준이므로 같은 종목을 NH 밖 계좌(수동·다른 증권사)에도 보유하면 NH 입금이 있어도
  `NH 일부 확인`(`nh_partial`)이고 수취 입력은 그대로 둔다(그 계좌 몫은 NH로 확인할 수 없다).
- NH 연동 계좌에만 보유한 종목에 같은 종목·통화의 NH 배당(수취일 ±10일)이 이미 있으면 수동 수취 미리보기·저장을
  서버가 거절한다(409). 수동 계좌 현금이 중복으로 늘지 않게 한다.
- 수입·입출금 내역: NH 배당 행은 `NH 확인`, 환율·세금 검산 실패나 증권사 정정은 `확인 필요`.
- API: `GET /api/portfolio/dividend-receipts` 항목과 `/api/portfolio/dividend-calendar` 이벤트에 `verification`
  (`nh_confirmed`|`nh_partial`(캘린더만)|`unconfirmed`|null)과 `nh_match`(NH 날짜·금액), 거래내역 항목에 `verification`(`nh_confirmed`|`needs_review`).

### 계속 보류하는 것

- 이자·예탁금이용료·대여수수료·입출금·환전 등 배당 외 모든 종합거래내역 자동 반영.
- 국내 배당·분배금 취소/정정 행, 해외 출금(`02`)으로 오는 배당 취소: 자동 반영하지 않는다(원 배당은 유지).
- 국내 ETF·ETN 분배금 적요는 12개월 동안 관찰되지 않았다. `분배금` 적요는 같은 규칙으로 가져오며,
  `/krstock/inquiry/v1/rightsHeld`(07 ETF·17 ETN 분배금) 대조는 아직 사용하지 않는다.
- 외화주식 외 종목 중분류(00004·00005)는 운영 0건이라 조회하지 않는다.

## 현금·수익률 계약

정상 조회한 잔고 스냅샷과 수입·입출금 원장은 같은 DB 트랜잭션에서 반영한다.
거래내역 식별자 등이 누락되면 원장은 갱신하지 않고 잔고와 거래내역 보류 상태만 함께 반영한다.
수입 원장은 현금에 가산하지 않는다. 배당·이자·기타 수입은 수익 분해에 별도로 나타난다.
같은 계좌·종목·수취일(±5일)·통화·실수령액(반올림 허용)의 기존 수동 배당 수취가 있으면 중복 분류하지 않는다.

최초 가져온 과거 입출금은 시작 잔고에 포함된 기록으로 보존하며 NAV 좌수를 다시 만들지 않는다.
추적 시작 이후 새 원금 입출금만 현금 변경 없이 NAV 입출금 원장에 반영한다.
분류 정정은 이미 정산한 내역을 삭제하지 않고 현재 시점 차액으로 보정한다.
NH 원금 입출금은 기존 수동 입출금 삭제 기능으로 현금을 되돌릴 수 없다.

외화는 원통화별 수입을 우선 표시한다. 명세의 적용환율에는 환산 단위가 명시되지 않아
1 외화당 원화 환율을 사용자가 확인하기 전에는 원화 수익 분해·NAV 입출금에서 제외한다.
해외 배당만 원화 과세표준으로 환율을 행마다 검산한 경우 NH 적용환율을 그대로 사용한다.
미확인 거래가 있는 동안 원화 성과는 완전한 분류가 아니다. 오늘의 환율을 과거 거래에
소급 적용하지 않는다.
