# 매매 기록

보유종목 화면의 **매매 기록** 버튼 또는 종목 행의 **매매** 버튼으로 연다. 종목을 검색하고 매수/매도, 수량, 체결 단가, 수수료·세금을 입력한 뒤 변경 내용 확인 → 매매 기록 저장 순서로 기록한다. 새 종목도 검색해 바로 매수할 수 있다. 최근 20건의 기록은 같은 창 아래에 표시한다.

## 현금 환전

현금 행의 **환전** 버튼 또는 매매 기록 창에서 `CASH_KRW`, `CASH_USD` 등 현금을 선택하면 같은 창이 환전 입력으로 전환된다. 받는 통화·환전 금액·체결 환율·수수료를 입력하고 **변경 내용 확인 → 환전 기록 저장**으로 기록한다. 매매와 환전은 같은 최근 내역에 시간순으로 표시한다.

- 환율 표시 기준을 선택할 수 있다. 원화↔달러는 기본으로 **1 USD = ? KRW**다. `to_per_from`은 보내는 통화 1단위당 받는 통화, `from_per_to`는 받는 통화 1단위당 보내는 통화다. 기준이나 받는 통화를 바꾸면 잘못된 재사용을 막기 위해 환율을 비운다.
- 수수료는 보내는 통화로 입력하고 환전 금액에 더해 차감한다. 환율에 이미 포함된 비용은 별도 수수료를 0으로 입력한다. 실제 수령액을 직접 입력하면 환율 계산보다 우선한다. 수령액 자동 계산은 받는 통화의 최소 금액 단위로 사사오입한다.
- 예: KRW 140,000원, 환율 1 USD = 1,400 KRW, 수수료 1,000원이면 KRW 141,000원을 차감하고 USD 100을 더한다.
- 두 현금 잔고와 `portfolio_trades` 원장을 같은 트랜잭션에 저장한다. 받는 통화의 현금 항목이 없으면 만들고, 기존 현금 설정은 보존한다. 잔고 부족·같은 통화·잘못된 금액 단위·저장 정밀도 초과는 차단한다.
- 환전은 내부 자산 이동이므로 외부 입출금·NAV 좌수를 만들지 않는다. 수수료와 체결 환율 대비 평가 환율 차이는 자산 가치에 반영된다. 배당 수취·미분배 누계의 통화는 이 환전으로 재분류하지 않는다.
- 동일한 `/api/portfolio/trades/preview` 및 `/api/portfolio/trades` POST/GET을 사용한다. `side: "exchange"` 입력은 `from_currency`, `to_currency`, `amount`, `rate`, `rate_basis`, `fees`, 선택적 `received_amount`, `memo`를 받는다. 주식의 기존 buy/sell 요청은 그대로 유지한다.
- 미리보기는 양쪽 잔고를 함께 읽으며, 어느 쪽이든 변경되면 409로 재확인을 요구한다. 응답 유실과 중복 요청은 기존 매매와 같은 요청 번호로 복구한다. 포트폴리오 기록만 변경하며 은행·증권사에 환전 주문을 전송하지 않는다.

## 주식 매매

2026-09-09: 수수료와 세금을 나눠 입력한다. 국내 종목 코드의 매도는 거래세율 **0.2% (농특세 포함)**를 기본으로 채우며, 수량·단가 변경 시 세금과 총비용을 다시 계산한다. 매수·해외 종목은 기본 0%다. ETF 등 비과세 거래는 세율을 0으로 바꾸고, 실제 정산액이 다르면 세금 직접 입력을 사용한다. 세율 계산은 통화 최소 단위 미만을 버리며, 서버 미리보기가 최종 금액이다. 국내 기본값 참고: [KB증권 2026년 증권거래세율 변경 안내](https://www.kbsec.com/go.able?idt=20251218&linkcd=s060901010000&seq=10009325).

API `fees` 입력은 매매 수수료, `tax_rate`는 백분율, `tax_amount`는 선택적인 세금 확정액이다. 응답 `fees`는 합계, `commission`과 `tax_amount`는 구성 내역이다. 이전 클라이언트는 세금까지 포함한 `fees`를 보내므로 새 필드를 생략하면 추가 과세하지 않는다. 배포 전 응답 유실 요청의 지문과 과거 원장도 유지한다.

- 매수: 같은 통화의 `CASH_{통화}`에서 체결 금액과 비용을 차감하고 보유 수량을 늘린다. 비용을 포함한 가중평균 매입가를 계산한다.
- 매도: 체결 금액에서 비용을 뺀 금액을 같은 통화의 현금에 더한다. 부분 매도는 평균 매입가를 유지하며, 전량 매도는 보유 행과 태그를 제거한다. 매도 통화의 현금 행이 없으면 만든다.
- 현금 부족·보유 수량 초과·롱숏 페어·공매도·지수·선물은 차단한다. 현금과 종목에 대한 기존 개별 수정 기능은 계속 사용할 수 있다.
- 기존 외화 종목의 매입가 통화가 체결 통화와 다르면 추가 매수 때 체결 환율을 직접 입력한다. 예: 체결 USD, 기존 매입가 KRW라면 **1 USD당 KRW**. 외부의 현재 환율을 과거 체결 환율로 대신하지 않는다.
- 체결 금액은 KRW/JPY/VND 정수, 그 외 지원 통화 소수 2자리로 사사오입한다. 수수료·세금도 같은 통화 단위로 입력한다. 수량·단가는 최대 소수 8자리다.
- 기록 시점의 현재 잔고에 반영한다. 과거 거래일/NAV 재작성, 거래 취소, 손익 원장 재구성, 증권사 주문 전송은 제공하지 않는다. 거래 비용은 현금과 매입가·매매 내역에 포함되며 수익 분해의 별도 비용 분류를 자동 생성하지 않는다.

API는 `/api/portfolio/trades/preview` POST, `/api/portfolio/trades` POST/GET이다. 입력과 응답에 Pydantic 모델을 적용했다. 인증된 사용자의 잔고만 조회·수정한다.

미리보기는 `read_snapshot()`으로 종목과 현금을 읽고 상태 지문을 반환한다. 저장은 `transaction()`의 `BEGIN IMMEDIATE` 안에서 지문을 다시 비교하고, **종목 → 현금 → portfolio_trades 기록**을 함께 커밋한다. 중간 오류는 모두 롤백하며 포트폴리오 입출금이나 NAV 좌수를 생성하지 않는다.

`(google_sub, request_id)`를 유일 키로 사용한다. 동일한 요청의 재시도는 최초 저장 결과만 반환하고 잔고를 다시 변경하지 않는다. 응답이 끊기면 화면은 입력을 잠그고 **저장 결과 확인**을 제공하며, 사용자별 sessionStorage에 요청을 보관해 같은 탭에서 새로고침해도 같은 요청 번호를 사용한다. 미리보기 이후 잔고가 바뀐 경우에는 409로 재확인을 요구한다.

프론트는 `portfolio-trades.js`를 `trades` 지연 로딩 그룹으로 등록한다. `portfolio-events.js`가 버튼을 위임 처리하며, 기본 화면의 초기 스크립트 요청 수를 늘리지 않는다. native dialog의 포커스 관리와 모바일 크기를 사용한다.

회귀 검사는 원자적 롤백, 동시 요청, 미리보기 후 변경, 중복 요청, 사용자 격리, 현금·수량·매입가 계산, 외화·소수 수량, 응답 유실 재시도, 데스크톱·모바일 실제 DB 저장을 다룬다.

배당 수취·분배금 출금은 [배당금과 분배금](dividend-receipts.md)을 따른다.
