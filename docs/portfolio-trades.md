# 매매 기록

보유종목 화면의 **매매 기록** 버튼 또는 종목 행의 **매매** 버튼으로 연다. 종목을 검색하고 매수/매도, 수량, 체결 단가, 수수료·세금을 입력한 뒤 변경 내용 확인 → 매매 기록 저장 순서로 기록한다. 새 종목도 검색해 바로 매수할 수 있다. 최근 20건의 기록은 같은 창 아래에 표시한다.

- 매수: 같은 통화의 `CASH_{통화}`에서 체결 금액과 비용을 차감하고 보유 수량을 늘린다. 비용을 포함한 가중평균 매입가를 계산한다.
- 매도: 체결 금액에서 비용을 뺀 금액을 같은 통화의 현금에 더한다. 부분 매도는 평균 매입가를 유지하며, 전량 매도는 보유 행과 태그를 제거한다. 매도 통화의 현금 행이 없으면 만든다.
- 현금 부족·보유 수량 초과·롱숏 페어·공매도·지수·선물은 차단한다. 현금과 종목에 대한 기존 개별 수정 기능은 계속 사용할 수 있다.
- 기존 외화 종목의 매입가 통화가 체결 통화와 다르면 추가 매수 때 체결 환율을 직접 입력한다. 예: 체결 USD, 기존 매입가 KRW라면 **1 USD당 KRW**. 외부의 현재 환율을 과거 체결 환율로 대신하지 않는다.
- 체결 금액은 KRW/JPY/VND 정수, 그 외 지원 통화 소수 2자리로 사사오입한다. 수수료·세금도 같은 통화 단위로 입력한다. 수량·단가는 최대 소수 8자리다.
- 기록 시점의 현재 잔고에 반영한다. 과거 거래일/NAV 재작성, 거래 취소, 손익 원장 재구성, 증권사 주문 전송은 제공하지 않는다. 거래 비용은 현금과 매입가·매매 내역에 포함되며 수익 분해의 별도 비용 분류를 자동 생성하지 않는다.

API는 `/api/portfolio/trades/preview` POST, `/api/portfolio/trades` POST/GET이다. 입력과 응답에 Pydantic 모델을 적용했다. 인증된 사용자의 잔고만 조회·수정한다.

미리보기는 `read_snapshot()`으로 종목과 현금을 읽고 상태 지문을 반환한다. 저장은 `transaction()`의 `BEGIN IMMEDIATE` 안에서 지문을 다시 비교하고, **종목 → 현금 → portfolio_trades 기록**을 함께 커밋한다. 중간 오류는 모두 롤백하며 포트폴리오 입출금이나 NAV 좌수를 생성하지 않는다.

`(google_sub, request_id)`를 유일 키로 사용한다. 동일한 요청의 재시도는 최초 저장 결과만 반환하고 잔고를 다시 변경하지 않는다. 응답이 끊기면 화면은 입력을 잠그고 **저장 결과 확인**을 제공하며, 사용자별 sessionStorage에 요청을 보관해 같은 탭에서 새로고침해도 같은 요청 번호를 사용한다. 미리보기 이후 잔고가 바뀐 경우에는 409로 재확인을 요구한다.

프론트는 `portfolio-trades.js`를 `trades` 지연 로딩 그룹으로 등록한다. `portfolio-events.js`가 버튼을 위임 처리하며, 기본 화면의 초기 스크립트 요청 수를 늘리지 않는다. native dialog의 포커스 관리와 모바일 크기를 사용한다.

회귀 검사는 원자적 롤백, 동시 요청, 미리보기 후 변경, 중복 요청, 사용자 격리, 현금·수량·매입가 계산, 외화·소수 수량, 응답 유실 재시도, 데스크톱·모바일 실제 DB 저장을 다룬다.
