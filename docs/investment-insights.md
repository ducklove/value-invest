# 투자 논거 추적과 수익 원인 분해

## 화면과 사용법

포트폴리오 → 심층 분석에서 `수익 원인 분해`와 `투자 논거 · 반증 조건`을 연다. 모바일 간편 보기에서는 `일반`으로 전환하면 심층 분석 탭이 나타난다.

수익 분해는 기간 선택 후 바로 조회한다. 저장된 보고서가 없어도 사용할 수 있다. 새로 생성·갱신하는 월간·연간 보고서는 같은 분해 결과를 v4 스냅샷과 Markdown에 포함한다. 기존 보고서는 자동으로 다시 쓰지 않는다.

`실제 배당·비용 분류 기록`에는 이미 현금 잔고에 반영한 세후 배당금 또는 비용을 원화로 적는다. 이 기록은 분류만 수행하며 잔고나 입출금을 다시 늘리지 않는다. 수령 예정 배당은 배당 캘린더에서 확인한다. 미분류 금액을 줄이기 위해 실제 증거 없이 수입을 넣으면 안 된다.

투자 논거는 직접 등록하거나 투자일지의 `투자 논거로 추적`에서 연결한다. 논거, 반증 조건, 검토 기한, 근거 원문을 기록한다. 자동 점검은 저장된 연간 재무자료의 매출 전년 대비 증감률, 영업이익률, 부채비율을 지원한다. 자료가 없거나 오래됐으면 정상으로 간주하지 않는다. 비재무 촉매는 직접 확인 조건으로 기록한다.

조건 충족·기한 도래·자료 부족은 기존 액션 보드의 검토 목록에 표시한다. 화면 조회 시 점검하며 외부 메시지를 자동 발송하지 않는다. 점검값·근거·판정이 바뀔 때만 이력을 남기고 새 액션 키를 발급한다. 같은 증거를 다시 조회해도 이력이 늘어나지 않는다. 보관 시 추적을 멈추고 재개할 수 있다.

## 수익 분해 계산

기준일은 요청 시작일 직전 마지막 일별 스냅샷이다. 없으면 기간 내 첫 스냅샷을 쓰고 화면에 표시한다. 종료일도 실제 마지막 스냅샷 날짜를 명시한다.

`자산 증감 = 순입출금 + 가격 효과 + 환율 효과 + 가격·환율 미분리 + 기록한 배당 - 기록한 비용 + 매매·기타 미분류`

`순입출금 제외 손익 = 종료 평가액 - 시작 평가액 - 순입출금`

인접 스냅샷에서 수량이 같은 종목만 가격 기여분을 계산한다. 수량을 q, 현지가격을 p, 원화 환율을 r이라고 하면:

- 가격 효과: q × (p1 - p0) × r0
- 환율 효과: q × p1 × (r1 - r0)
- 가격과 환율의 상호작용은 환율 항목에 포함한다.
- 현지가격은 저장된 원화 단가와 당시 환율로 역산하므로 정산·반올림 시점에 따른 추정이다.
- 숏 포지션은 음수 수량을 그대로 사용한다. 외화 현금의 동일 수량 구간은 환율 효과로 분류한다.
- 과거 환율 이력이 없으면 원화 변동을 `가격·환율 미분리`로 표시한다. 현재 환율을 과거에 적용하지 않는다.
- 종목별 통화와 정산 시점의 신선한 환율 캐시를 새 스냅샷에 저장한다. 추가 외부 요청 없이 메타데이터를 수집하며 환율을 확보하지 못하면 NULL로 남긴다.
- 수량 변경, 신규·매도, 대체 시세, 단가·수량 불일치 구간은 가격 손익을 억지로 만들지 않는다. 해당 영향은 미분류로 남긴다.
- 합계를 맞추는 잔차는 확인되지 않은 원인을 드러내는 항목이며, 합계 검산 0원이 데이터 완전성을 뜻하지 않는다.
- 체결 원장이 없어 같은 날 사고판 거래나 기업행동은 구별할 수 없다. NAV 시간가중 수익률의 기여도와 구분한다.

## 자료와 경계

`portfolio_snapshots` → 기준 평가액, `portfolio_stock_snapshots` → 일별 수량·원화 단가·통화·환율, `portfolio_cashflows` → 반영일 기준 외부 입출금, `portfolio_income_events` → 사용자가 확인한 실제 수입·비용 분류.

`investment_theses` → 사용자별 논거와 규칙, `investment_thesis_checks` → 변경 이력. 연결 일지는 본인·동일 종목만 허용한다. 일지를 삭제해도 논거는 남고 연결만 해제한다. 모든 읽기·쓰기는 사용자 소유권을 확인한다. 조회한 규칙이 평가 저장 전 수정되면 오래된 판정을 기록하지 않는다.

연간 자료의 기준 연도와 보고일을 표시한다. 최근 공시 링크는 검토를 돕는 별도 근거이며 자동 점검 지표의 정확한 원문이라고 주장하지 않는다. 매출 성장률은 연속된 두 연도와 양수 기준 매출이 있어야 계산한다. 영업이익률의 매출, 부채비율의 자기자본이 0 이하이면 자료 확인이 필요하다.

스키마 추가는 idempotent이며 기존 데이터는 그대로 유지한다. 이후 확장 시 체결 원장·기업행동·배당 자동 수집을 먼저 확보해야 매매 구간의 실현손익과 종목별 총수익을 더 정확하게 설명할 수 있다.
