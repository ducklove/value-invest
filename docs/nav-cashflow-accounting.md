# NAV와 입출금 정산

입출금 입력은 원화 잔고를 즉시 변경한다. 입력한 날짜는 거래 기록용이며,
손익과 NAV의 귀속은 잔고에 실제 반영된 시점과 `applied_snapshot_date`로 판단한다.
미래 날짜는 예약 거래로 지원하지 않으므로 입력 단계에서 거절한다.

## 정산과 실시간 표시

- 정산 전후의 보유 목록·입출금 원장·직전 스냅샷이 같을 때만 저장한다.
  시세 조회 중 입력이 바뀌면 최대 3회 계산하고, 계속 바뀌면 저장하지 않는다.
- 신규 입출금의 발행 기준가는 `(평가액 - 순입출금) / 기존 좌수`다.
  입금은 좌수를 발행하고 출금은 회수하므로 입출금 자체가 수익률을 바꾸지 않는다.
- 잔고를 읽은 시각은 `cashflow_cutoff_at`에 저장한다. 20:00 고정 마커는
  실제 시각이 없는 과거 자료에만 사용한다.
- NAV·입출금 반영 마커·종목 및 그룹 스냅샷은 한 트랜잭션으로 저장한다.
- 실시간 NAV는 좌수가 아직 없는 입출금을 평가액에서 제외한다.
  Today 이후의 거래도 최신 NAV에 이미 반영됐다면 좌수를 다시 더하지 않는다.
- Today, MTD, YTD, 알림, 기기 요약과 브리핑은 같은 정산 귀속 규칙을 사용한다.

## 취소

미정산 거래는 삭제하면서 원화 잔고를 되돌린다. 이미 정산된 거래는 원거래와
과거 NAV를 보존하고 현재 날짜의 반대 거래를 추가한다. 원거래에는 취소 시각,
반대 거래에는 `reversal_of_id`를 기록한다. 중복 취소는 잔고를 다시 바꾸지 않는다.
원화를 빼야 하는 취소에서 잔고가 부족하면 전체 변경을 거절한다.

## 과거 발행 기준가 복구

```bash
python scripts/repair_nav_cashflow_pricing.py --db /path/to/cache.db
python scripts/repair_nav_cashflow_pricing.py --db /path/to/cache.db --apply --refresh-reports
```

첫 명시적 입출금 이전의 좌수를 기준점으로 보존한다. 이후 좌수 증감이 원장과
일치할 때만 기록된 평가액·반영 정산일로 발행 기준가를 재계산한다. 원장 밖의
좌수 변동이나 기준점 누락은 추정하지 않고 중단한다. 미정산 거래와 평가액,
현재 보유 수량 및 현금은 변경하지 않는다.

적용 전 SQLite 온라인 백업과 무결성 검사를 수행한다. 점검 이후 데이터가
바뀌면 적용을 중단한다. 백업 및 변경 명세는 DB 옆 `.deploy-repairs/nav-pricing-*`
폴더에 남긴다. 적용 후 같은 계산을 다시 수행해 추가 변경이 없는지 확인한다.
저장 보고서는 `--refresh-reports`로 정정한 NAV에서 다시 생성한다.

정산된 NAV와 종목별 평가액 합이 다른 과거 자료는 보고서에 차이를 표시한다.
원자료가 없는 구간은 값을 임의로 맞추지 않는다.
