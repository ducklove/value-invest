# 프로젝트 검토 후 개선 및 기능 제안

## 반영한 개선

- **DB 무결성:** 공유 연결을 쓰는 저장 함수 68개의 트랜잭션 경계를 통일했다. 동시 초기화도 한 연결로 직렬화하며, 커밋 실패도 롤백한다. 독립 연결의 자체 트랜잭션과 시작 시 스키마 초기화는 별도다.
- **환산 정확성:** 환율이 없거나 만료된 경우 1:1로 환산하지 않는다. 평가를 보류하고 오류를 전달한다. 외화 매입가 수정은 기존 통화를 보존하고 저장 전에 환율을 확인한다.
- **입력 검증:** 비유한 숫자, 잘못된 날짜·불리언, 범위를 벗어난 금액·수량을 저장 전에 거절한다. 일괄 추가는 전체 성공 또는 전체 롤백으로 처리한다.
- **장애 감지:** IP 제한은 연결 계층에서 확인한 주소를 사용한다. 데이터 품질 오류는 HTTP 503으로 반환하며, 프로세스 응답(`/healthz`)과 DB 준비(`/readyz`)를 분리했다.
- **배포 복구:** 별도 소스 디렉터리와 커밋별 Python 환경에서 검사한 후 운영을 전환한다. 재시작·준비 검사 실패 시 코드, 실행 환경, 유닛, 타이머 상태를 함께 복구한다. 데이터 보정 스크립트는 코드 롤백과 별도로 처리한다.
- **재현성과 화면 진입:** Python 패키지를 버전과 해시로 고정하고, Markdown 처리 라이브러리를 저장소에서 제공한다. 요청한 화면을 먼저 열고 부가 정보를 병렬로 준비한다.
- **검증:** 기존 Python·JavaScript 검사에 동시 쓰기, 환율 장애, 잘못된 입력, 준비 검사, 배포 실패 주입 및 실제 브라우저 로그인·저장·새로고침·WebSocket 재접속 검사를 추가했다.

## 실제 투자 판단을 돕는 추가 기능

| 우선순위 | 기능 | 기존 기능을 확장하는 방식 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 투자 논거와 반증 조건 추적 | 투자일지의 매수 이유에 재무지표·공시·판단 기한을 연결하고 액션 보드에서 변화만 보여준다. | 조건 위반 시 근거 원문, 기준값, 현재값, 변경 시점을 함께 표시한다. |
| 2 | 수익 원인 분해 | 기존 수익률 리포트를 주가 변동·환율·배당·입출금으로 분해한다. | 항목 합계가 실제 평가손익과 일치하고, 데이터 누락과 잔차를 별도로 표시한다. |
| 3 | 시나리오별 적정가와 안전마진 | 기존 목표가 수식을 보수·기본·낙관 가정으로 확장한다. | 가정별 적정가, 현재가 대비 여유, 이전 가정 대비 변화와 계산 근거를 저장한다. |
| 4 | 새 자금 배분 시뮬레이터 | 기존 리밸런싱에 추가 입금·배당 재투자 시나리오를 넣는다. | 입력한 자금 한도 안에서 종목별 수량, 남는 현금, 목표 비중 오차를 비교하고 실제 저장 전 검토할 수 있다. |

먼저 투자 논거 추적과 수익 원인 분해를 권한다. 이미 쌓인 일지·공시·시세·스냅샷을 활용하면서, 매매 판단의 근거와 결과를 연결할 수 있다. 1·2번 기능은 후속 요청으로 구현했다. 사용법과 계산 범위는 [투자 판단 도구](investment-insights.md)를 참고한다. 3·4번은 제안 상태다.
