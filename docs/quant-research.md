# 퀀트 운용실 1차 구현

2026-09-16. 전체 방향은 [자동매매 기획](algorithmic-trading-plan.md)을 따른다.

## 사용 흐름

로그인 후 **도구 → 퀀트 운용실**(`/quant`)에서 보통주·우선주 쌍, 평가 기간,
추정창과 진입·복귀 기준, 비용을 입력한다. 실행 후 화면을 닫아도 연구는 서버에서 계속된다.
실험을 열면 상대가치 교체·보통주 보유·우선주 보유·고정 혼합의 가격 수익과
최대 낙폭, 추정 비용, 가상 체결을 비교한다. 비용 2배 시나리오도 함께 제공한다.
결과와 입력 원본을 JSON으로 내려받아 보관할 수 있다.

완료된 실험에서 일별 신호 관찰을 시작하면 동일 설정으로 새 완료 일봉의 판단을 기록한다.
수집 미완료, 입력 자료 정정, 엔진 변경, 최신 일봉 불일치가 있으면 이유를 표시하고 보류한다.
관찰은 가상 체결 수익이나 실주문이 아니다. 취소·관찰 중지는 언제든 가능하다.

## 이번 단계의 경계

- 보통주·우선주의 **매수 보유와 교체 연구**다. 공매도나 무위험 차익거래가 아니다.
- 수정주가를 연구용 단위로 사용한다. 실제 주문 주수, 배당 포함 총수익으로 해석하면 안 된다.
- 전 관측일 신호를 다음 관측일 가격으로 평가하며, 종가·정률 슬리피지 가정이다.
  호가 순서·동시 체결·실제 종가 주문 체결을 증명하지 않는다.
- 거래대금 참여 한도, 거래정지·관리·정리매매 상태, 가용 현금과 매도 비용을 반영한다.
  초기 매수 후 매일 같은 비중으로 자동 재배분하지 않고 수량 변화를 추적한다.
- 입력 비용은 사용자가 정하는 연구 가정이다. 계좌별 실제 수수료·시점별 세율 자동 적용은 후속 단계다.
- 현재 확인된 종목 관계를 사용하므로 생존편향이 있다. 모든 과거 거래일의 완전성을 보증하지 않는다.
- ETF 비교, 복합 팩터 바스켓, 외부 평가 구간 검증, 체결 기반 가상운용, NH 주문은 아직 미구현이다.

## 구성과 운영

| 구성 | 역할 |
| --- | --- |
| finance-pi `research/pairs.py` | 관계 확인, 입력 동결·해시, 신호 및 수량·현금 시뮬레이션 |
| finance-pi `/api/research/pairs`, `/api/research/pair-analysis` | 기존 관리자 인증을 사용하는 읽기 전용 연구 API |
| value-invest `services/quant` | finance-pi 연결, 엔진·설정·입력 해시 검증, 연구·관찰 작업자 |
| `repositories/quant.py` | 사용자별 실험, 재시작 복구, 관찰 원본 및 상태 저장 |
| `/api/quant/*`, `static/js/quant.js` | 인증된 사용자 API와 화면 |

기존 `CLOSE_PRICE_API_ENABLED`, `CLOSE_PRICE_API_BASE_URL` 설정과 API 토큰을 재사용한다.
실제 환경 변수명은 `close_price_client.py`가 기준이다. 새 증권사 비밀키는 요구하지 않는다.
연구는 전역 대기 10개, 사용자당 보관 100개, 활성 관찰 5개로 제한한다.
finance-pi는 동시 연구 1개만 허용한다. 결과는 건당 8MB 이내이며 주문 실행 권한은 없다.
현재 단일 앱 프로세스에서 실행한다. 다중 프로세스 전환 전 작업 임대·소유권을 추가해야 한다.

서비스 재시작 시 진행 중 연구는 대기로 복구한다. 취소된 작업의 늦은 응답은 저장하지 않는다.
매번 결과와 설정, 입력 해시가 일치해야 성공 처리한다. 관찰 기록에는 원래 스냅샷과 추가 일봉을 연결한다.
데이터레이크의 기존 가격·지표를 수정하는 API는 추가하지 않았다.

## 다음 단계의 통과 조건

1. 원주가·배당·권리 이력 및 당시 종목군을 검증하고 거래일 누락 검사를 완성한다.
2. 동일 지수·환헤지·분배금 조건이 확인된 ETF 쌍과 시점 보장 팩터 바스켓을 추가한다.
3. 사전 고정한 외부 평가 구간과 비용·유동성 스트레스를 통과시킨다.
4. 실시간 호가와 주문 상태 전이를 재생하는 가상운용으로 중복·부분체결·연결 장애를 검증한다.
5. 운용 계좌·예산·손실 한도를 지정하고 NH 주문 계약·복구 조회를 검증한 뒤 제한 실거래로 진행한다.

단순 백테스트 수익률이나 서비스 정상 기동만으로 다음 단계에 승격하지 않는다.
