# 퀀트 운용실 구현 안내

2026-09-16. 전체 방향은 [자동매매 기획](algorithmic-trading-plan.md)을 따른다.

현물·개별주식선물과 ETF·지수선물의 가정 시뮬레이션·호가 재생을 추가했다.
사용법·회계 가정·실거래 전제는 [현선물 차익 연구](futures-basis-research.md)를 참고한다.

## 사용 흐름

### 전문 데이터 공급 경로

우선주 관계·권리·배당 관측 자료는 common_preferred_spread, ETF 상품·연구 후보는 EIAYN이
버전 JSON API로 제공한다. finance-pi가 해시·신선도·종목 관계를 검사하고 보관하며 가격 이력과
백테스트를 담당한다. value-invest는 종목 선택 때 카탈로그 버전을 고정해 대기열에 저장한다.
보고서에서 공급자·기준일·카탈로그 해시를 확인할 수 있다.

현재 엔진은 `preferred-switch-3` / `etf-switch-3`다. 가격 계산은 v2와 같고 입력 계약이 바뀌었다.
기존 결과는 보존된다. v2 결과의 관찰·전진 평가를 이어가려면 새 연구를 등록해야 한다.
공급 API 장애·14일 초과 자료·상품 조건 변경 시 새 연구와 관찰을 보류한다.
배당·분배금 총수익과 실거래 주문은 여전히 활성화하지 않는다.

로그인 후 **도구 → 퀀트 운용실**(`/quant`)에서 보통주·우선주 또는 ETF 쌍, 평가 기간,
추정창과 진입·복귀 기준, 비용을 입력한다. 실행 후 화면을 닫아도 연구는 서버에서 계속된다.
실험을 열면 상대가치 교체·보통주 보유·우선주 보유·고정 혼합의 가격 수익과
최대 낙폭, 추정 비용, 가상 체결을 비교한다. 비용 2배 시나리오도 함께 제공한다.
결과와 입력 원본을 JSON으로 내려받아 보관할 수 있다.

완료된 실험에서 일별 신호 관찰을 시작하면 동일 설정으로 새 완료 일봉의 판단을 기록한다.
일봉 수집 미완료, 입력 자료 정정, ETF 검토 기준·엔진 변경, 최신 일봉 불일치가 있으면 이유를 표시하고 보류한다.
관찰은 가상 체결 수익이나 실주문이 아니다. 취소·관찰 중지는 언제든 가능하다.

## 이번 단계의 경계

- 보통주·우선주의 **매수 보유와 교체 연구**다. 공매도나 무위험 차익거래가 아니다.
- 수정주가를 연구용 단위로 사용한다. 실제 주문 주수, 배당 포함 총수익으로 해석하면 안 된다.
- 전 관측일 신호를 다음 관측일 가격으로 평가하며, 종가·정률 슬리피지 가정이다.
  호가 순서·동시 체결·실제 종가 주문 체결을 증명하지 않는다.
- 거래대금 참여 한도, 거래정지·관리·정리매매 상태, 가용 현금과 매도 비용을 반영한다.
  초기 매수 후 매일 같은 비중으로 자동 재배분하지 않고 수량 변화를 추적한다.
- 입력 비용은 사용자가 정하는 연구 가정이다. 계좌별 실제 수수료·시점별 세율 자동 적용은 후속 단계다.
- 현재 확인된 종목 관계를 사용하므로 생존편향이 있다. 모든 과거 거래일의 완전성을 보증하지 않는다.
- ETF 가격비 연구와 사후 기간 분할 진단을 추가했다. 복합 팩터 바스켓, 미관측 외부 평가,
  체결 기반 가상운용, NH 주문은 아직 미구현이다.

## 2차 확장: ETF·기간 진단·관찰 의존성

### ETF 연구 후보

KODEX 200(069500) / TIGER 200(102110)을 첫 연구 후보로 등록했다.
기초지수 확인 근거는 [KODEX 공식 상품 자료](https://www.samsungfund.com/etf/product/view.do?id=2ETF01)와
[TIGER 200 KRX 상품 공시](https://kind.krx.co.kr/disclosure/etfisudetail.do?method=searchEtfIsuSummary&strIsurCd=10211)다.
검토일은 2026-09-16이며, 과거 분배·복제·비용 정책의 일치가 검증된 등가 거래쌍은 아니다.
검토 메타데이터와 출처를 입력 스냅샷에 저장한다. 임의 ETF·레버리지 상품 조합은 거절한다.

신호는 `log(ETF A 가격 / ETF B 가격)`을 이전 추정창의 평균·표준편차와 비교한다.
ETF 한 좌당 가격 수준이 달라도 단위 배수에 영향을 받지 않는다.
평균 대비 B의 상대가격 하락 폭이 진입 z 기준과 왕복 교체 비용을 모두 넘어야 B를 목표로 한다.
왕복 비용 가정은 `수수료×4 + 체결 손실×4 + 매도세×2`다. A→B→A의 네 거래를 가정한다.
평균 복귀 폭은 기대수익 예측이나 iNAV 괴리율이 아니다. 분배금 시점 차이는 여전히 미반영이다.
ETF 선택 시 매도세 연구 기본값을 0bp로 바꾸고 비용 입력란을 연다. 실제 계좌 비용은 사용자가 확인한다.
보수처럼 가격·NAV에 반영된 항목을 별도 운용보수로 다시 차감하지 않는다.

과거 ETF 거래대금은 누락된 날짜가 많다. 거래대금이 없고 거래량이 있으면
`수정종가×거래량`을 연구용 유동성 추정치로 사용하며, 관측 거래대금과 날짜 수를 나눠 표시한다.
기업행동에 따른 가격·거래량 단위의 차이가 있을 수 있어 실제 참여율이나 체결 가능 규모로 해석하면 안 된다.
거래 가능한 날에 거래대금·거래량이 모두 없으면 연구를 거절한다. 원본 데이터레이크의 누락값은 수정하지 않는다.
혼합 전략의 미체결 매수에는 두 자산의 필요 금액 비율로 현금을 배정해 한쪽이 전부 소비하지 않게 한다.
계산 변경에 따라 엔진은 `preferred-switch-2` / `etf-switch-2`다. 이전 결과는 보존하고 재연구가 필요하다.

### 기간별 진단

189개 이상의 평가 관측일을 시간순 세 구간으로 나누고, 각 구간에서 초기 현금으로 다시 평가한다.
각각 최소 63개 관측일을 확보하며 구간 종료 이후 가격은 해당 시뮬레이션에 전달하지 않는다.
혼합 보유를 고정 비교전략으로 사용하고 수익 차이·낙폭을 표시한다. 가장 좋은 구간이나 비교전략을 고르지 않는다.
비용 2배 비교도 교체와 혼합 보유 양쪽에 같은 배수를 적용한다.
이는 **사후 안정성 진단**이며 미관측 검증, 워크포워드 최적화 또는 실거래 승격 판정이 아니다.
기존 저장 결과는 변경하지 않으며, 새 연구부터 보고서에 추가된다.

### 일봉 관찰의 데이터 기준

`/api/research/readiness`는 카탈로그·가격 최신성·일별 완료 기록을 검사한다.
어제 이전의 최종 거래일과 가격 기준일이 같아야 한다. 미완료 날짜 목록이 잘렸거나,
가격 산출 여부·날짜·실패 원인이 불명확하면 차단한다.
완료 기록에서 거시지표 실패만 명확하게 확인된 경우 일봉 관찰은 허용한다.
전체 `/api/ready` 결과는 그대로 유지하고 화면에 전체 수집 상태와 일봉 관찰 가능 여부를 함께 보여준다.
관찰 시 대상 종목의 가격·거래상태·중복·기존 스냅샷도 추가 검증하고 사용한 readiness 근거를 기록한다.

| `repositories/quant.py` | 사용자별 실험, 재시작 복구, 관찰 원본 및 상태 저장 |

기존 `CLOSE_PRICE_API_ENABLED`, `CLOSE_PRICE_API_BASE_URL` 설정과 API 토큰을 재사용한다.
실제 환경 변수명은 `close_price_client.py`가 기준이다. 새 증권사 비밀키는 요구하지 않는다.
연구는 전역 대기 10개, 사용자당 보관 100개, 활성 관찰 5개로 제한한다.
finance-pi는 동시 연구 1개만 허용한다. 결과는 건당 8MB 이내이며 주문 실행 권한은 없다.
현재 단일 앱 프로세스에서 실행한다. 다중 프로세스 전환 전 작업 임대·소유권을 추가해야 한다.

서비스 재시작 시 진행 중 연구는 대기로 복구한다. 취소된 작업의 늦은 응답은 저장하지 않는다.
매번 결과와 설정, 입력 해시가 일치해야 성공 처리한다. 관찰 기록에는 원래 스냅샷과 추가 일봉을 연결한다.
데이터레이크의 기존 가격·지표를 수정하는 API는 추가하지 않았다.

## 다음 단계의 통과 조건

### 2026-09-16 추가 구현: 사전 고정 전진 평가

완료한 연구 보고서에서 **이 설정으로 전진 평가 시작**을 선택한다. 서버가 다음 한국 날짜를
시작일로 고정한다. 연구 설정·엔진·초기 가상 자금은 원래 연구와 동일하며 변경하지 않는다.
첫 평가 일봉은 신호만 생성하고, 두 번째 일봉부터 전일 신호에 따라 가상 체결한다.
교체 전략과 고정 혼합을 같은 초기 자금·비용·유동성 조건으로 비교한다.

이는 새 데이터를 사용하는 **일봉 재생 평가**다. 실시간 주문·호가 기반 모의체결이 아니며,
서버 중단 기간도 다시 재생한다. 수정주가 단위·배당 미반영 등 기존 연구의 한계가 유지된다.
기간이 지나기 전에는 성과를 만들지 않는다. 실제 주문은 항상 0건이다.
목표 수량은 집행일 종가에 따라 계산하므로 실제 사전 주문 수량을 재현한 것으로 해석하지 않는다.

- `quant_forward`에 시작일·생성 시각·상태와 마지막 검증 원장을 저장한다. 사용자당 활성 5개다.
- 등록 재시도는 같은 평가를 반환한다. 중지는 되돌리지 않으며 새 평가에는 새 연구가 필요하다.
- 작업자는 한 시간 간격으로 최신 완료 일봉을 확인한다. 재시작해도 같은 기간·설정을 유지한다.
- 기존 연구와 이후 추가 일봉까지 수정 여부를 확인한다. 자료가 달라지면 마지막 원장을 보존하고 보류한다.
- 원장 해시 외에 체결 가격·비용·참여율·거래정지·현금·수량·수익·낙폭을 서버에서 대조한다.
- 이미 기록한 체결·평가액은 이후 입력 추가로 변경할 수 없다. 중지 후 늦게 온 응답도 무시한다.
- 보고서에서 전진 평가 원장·입력·수집 상태를 JSON으로 내려받을 수 있다.
- 일반 신호 관찰도 원래 연구뿐 아니라 직전 관찰까지의 추가 일봉을 보호한다.

finance-pi `/api/research/pair-forward`는 `forward_start`를 받는 내부 읽기 전용 재생 API다.
사전 등록 사실과 시작일 강제는 value-invest가 담당한다. 직접 과거 시작일로 호출한 API 결과는
사전 등록 검증을 의미하지 않는다. `daily-forward-1` 원장 버전을 따로 기록한다.

### 비용·유동성 스트레스

새 연구 보고서는 비용 2배와 기존 참여율 한도의 50%/10%를 조합한 두 시나리오를 추가한다.
같은 신호를 유지하며 교체·혼합 양쪽에 동일한 제약을 적용하고 수익 차이·낙폭·종료 현금을 보여준다.
이는 체결 민감도 검사이며 강화한 비용으로 신호를 다시 최적화하거나 합격 전략을 고르는 과정이 아니다.
기존 연구 결과는 변경하지 않는다.

후보는 28행, 6개 종목으로 줄었다. 모든 팩터 계정의 완전성을 확인하기 전의 상한이다.
원천 `fnlttSinglAcntAll`의 정정 후 금액을 과거 공개일에 붙일 수 있다는 변환 코드의 제한도 확인했다.

추가 조사에서는 2026-04-01 전체 PIT 파티션에 평가일 당일·이후 접수 자료 377행(3종목),
2026-05-04에는 446행(4종목)이 있음을 확인했다. 예를 들어 4월 자료의 접수번호가
`20260619000667`이었다. `available_date`만 확인해서는 정정 후 금액의 미래 정보 누출을 막지 못한다.

새 `/api/research/factor-inputs`는 기본 최신 재무 파티션 또는 `as_of=YYYY-MM-DD`를
읽기 전용으로 검사한다. 평가일, 실제 접수일, 접수번호 일치, 통화·단위, 금액 기준,
역사적 일괄 수집 여부와 결산 후 550일 경과를 검사한다. 이익·자산·자본은 같은 공시·결산·
연결 범위에 속할 때만 완전 후보로 센다. 제외 사유는 중복 집계되며 결측 결과는 0으로 표시하지 않는다.
운용실 상단에 검사 기준일·가격 기준일·후보 수·제외 사유를 표시한다. 검사는 원본을 수정하지 않으며,
기존 PIT 데이터나 레거시 팩터 엔진의 오류를 복구했다는 의미도 아니다. 후보에 남아도 원공시·
당시 종목군·계정 우선순위의 추가 검증이 필요하다. 팩터 입력 검사 장애는 상대가치 연구와 분리된다.
[OpenDART 전체 재무제표 명세](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020)는
응답에 공시 접수번호와 통화 단위를 제공하므로 이 정보를 버리지 않고 검증 근거로 사용한다.
