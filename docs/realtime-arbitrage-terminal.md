# 실시간 현물·선물 차익 운용실

2026-09-16 · 사용자 요구 재정의 · 구현 목표이며 현재 서비스의 완료 목록이 아님

## 최신 합의와 구현 상태

사용자는 전체 시장의 순간 기회를 모두 포착할 필요 없이 **5~240분의 목표 주기(기본
60분)로 전체 주식선물·현물을 순회하고, 차이가 큰 후보만 실시간 감시하는 방식**을
선택했다. 아래 3절의 전체 동시 수집은 필수 조건이 아니다. 추가 시세 공급원 도입도
이번 구현의 전제가 아니다.

이번 구현은 전체 공개 마스터 표시, 나무 REST 순회, 후보 자동 선정, 두 번째 세션의
KRX 현물 `ob`/주식선물 `vH` 호가, 실시간 재평가·관측 기록까지다. 실행은 사용자가
연결 계좌를 골라 시작한다. 기존 계좌 시세 세션 1개를 유지하고 감시용 세션 1개에
최대 30등록(독립적인 15쌍)을 사용한다. 기본 감시 10쌍, 편입 30bp, 기회 50bp,
최소 유지 5분이며 연구 시작값으로 조정 가능하다. 진입 문턱의 절반 미만이 되면
최소 유지시간 이후 해제한다. 최대 두 순회 목표 주기를 지난 후보도 해제한다.

현물 매수·선물 매도의 만기 수렴 추정만 평가한다. 배당 수입 0, 현물 100%와
가정 증거금의 금융비용, 국내 현물 1bp·선물 0.6bp 편도 수수료, 매도세·슬리피지·
한쪽 미체결 여유를 차감한다. 현재는 주당 추정치이며 조정승수·권리·실제 증거금·
실제 청산가격의 검증을 대체하지 않는다. 역방향·대차 및 자동 가상/실제 주문은 미구현이다.

순회 호가는 최대 120초 지연·90초 시각 차이까지만 후보 판단에 사용한다. 실시간
기회 기록은 양쪽 호가 5초 이내·시각 차이 2초 이내·잔량 양수를 요구한다.
재연결하면 양쪽 기존 호가를 비우고 구독 승인과 새 호가를 모두 기다린다.
구독 실패 시 다른 연결을 강제로 해제하지 않는다. 주말·09:00~15:20 밖은 대기한다.
별도 휴장일·특별 개장일 달력 검증은 아직 없으며 이 관찰 시계를 실주문에 사용하지 않는다.
최소 유지시간 중이어도 관측 오류·만기·오래된 자료는 후보에서 제외한다.

REST는 계좌 조회와 같은 앱키 잠금·1.1초 호출 간격·429 대기를 공유한다. 실제 한 바퀴
소요시간을 표시하고 목표보다 늦어져도 조회 한도를 우회하지 않는다. 매 관측의 커서와
결과를 보관해 재시작 후 이어가며 새 설정의 generation과 다른 이전 작업 쓰기는 거절한다.
계약 마스터가 바뀌면 커서를 재설정한다. 연구 설정 변경은 이전 관측 표를 비우고
별도 기회 기록은 당시 비용·설정과 함께 보존한다. 호가 기록은 사용자당 최근 3,000건,
동일 쌍 최대 10초마다 표본화하되 문턱 돌파는 즉시 기록한다. 전체 틱 백테스트 자료가 아니다.

API는 로그인한 사용자에 한해 `GET/PUT /api/quant/scanner`,
`POST /api/quant/scanner/stop`이다. 정지는 폼 입력 오류·계좌 연결 해제와 무관하게
작동하며 주문을 생성하지 않는다. 실제 계좌 연동과 장중 호가 수신 검증,
finance-pi 틱 재생 연계·부분 체결 복구를 갖춘 주문 시스템은 후속 구현이다.

## 1. 제품의 중심

전체 선물 계약과 대응 현물의 관계를 자동 구성하고, 양쪽 실제 호가를 계속 비교한다.
체결 가능한 수량에서 비용 차감 우위가 발생하면 조건을 재검증해 두 포지션을 만들고,
차이 축소·만기·손실 한도에 따라 청산한다. 사용자가 종목과 가상 가격을 입력하는
현재 연구 화면은 이 요구를 충족하지 못하며 보조 분석으로 이동한다.

첫 범위는 국내 개별주식선물과 직접 대응 현물, 지수선물과 복제 바스켓/ETF다.
전체 선물은 검색 가능한 계약 목록에 포함하되 대응 현물을 거래할 수 없거나 결제·
단위·권리조정을 검증하지 못한 상품을 자동매매 가능으로 표시하지 않는다.
ETF 헤지는 추적 차이가 있는 상대가치 전략으로 구분한다.

## 2. 조사로 확인한 연결 조건

- [나무 공식 API 목록](https://www.nhplug.com/apiservice): 주식선물 호가/체결가,
  지수선물 호가, 국내 파생 주문·체결·주문가능수량·증거금 API가 있다.
- [국내 파생 REST 명세](https://www.nhplug.com/openapi-docs/krfuture/openapi.json):
  시세 외에 `/krfuture/inquiry/v1/orderable`, `/margin`, `/commission` 등이 있다.
- [주식선물 구조체](https://www.nhplug.com/instruments/m_stkfut.h)는 97바이트,
  CP949, 기초자산 코드 필드를 제공한다. [공개 마스터](https://www.nhplug.com/instruments/m_stkfut.mst)를
  읽은 결과 1,734개 계약 레코드·292개 기초자산이었다. 현재 거래 가능한 계약 수로
  해석하지 않는다. 원본 시각·만기·거래정지·권리조정을 추가 검증한다.
- 사용자 확인 조건: 세션당 30종목, 최대 2세션. 국내 현물 수수료 편도 0.01%,
  선물 편도 0.006%, 해외 현물 편도 0.09%. 세금과 금융비용은 별도다.
- 현재 코드는 국내 주식 체결가와 금현물 중심의 한 세션이다. 선물 호가 수집,
  두 세션의 공동 구독 관리, 실제 주문 상태 관리가 아직 연결되어 있지 않다.

## 3. 전체 탐색과 연속 감시

전 계약 카탈로그와 전 계약 실시간 호가는 다르다. 60종목을 번갈아 구독하거나 REST로
순회하는 방식은 비구독 구간의 순간적인 차익을 놓친다. 이를 전체 실시간 감시로
표시하지 않는다. 주식선물만 기초자산마다 한 월물을 고르더라도 292쌍은 60종목보다 크다.

두 수집 경로를 명시한다.

1. 전체 탐색: 계약 마스터, 거래대금·유동성·최근 관측으로 후보를 구성한다.
   수집 예산 안에서 스냅샷을 갱신하고 마지막 관측 시각과 미관측 구간을 기록한다.
2. 연속 감시: 실제 거래 후보와 보유 포지션의 양쪽 호가를 지속 구독한다.
   체결가가 아니라 매수/매도 호가와 단계별 수량으로 실행 가능성을 판단한다.

전체 시장 동시 호가가 목표라면 추가 시세 공급원·정식 한도 확장을 조사한다.
한도 우회용 키 증식이나 반복 연결로 해결하지 않는다. 기존 계좌 시세와 주문 통보도
같은 예산을 사용하므로 앱키별 소유자 하나가 구독을 배분한다. 보유 포지션,
미체결 주문, 청산 필요 종목을 신규 후보보다 우선하고 양쪽 중 한쪽만 확보한 후보는
거래하지 않는다. 동일 현물/헤지 계약은 중복 구독을 합친다.

## 4. 기회 판정과 실행

선물 고평가에서는 현물 매수호가가 아니라 **현물 매도호가에 매수**, 선물 매수호가에
매도하는 비용을 계산한다. 역방향은 현물 매수호가에 매도·선물 매도호가에 매수하며
실제 대차 및 매도 가능 확인이 필요하다. 최근 체결가 두 개의 차이만으로 주문하지 않는다.

기초가격·배당·잔존기간·금융비용으로 정상적인 가격 차이를 구분하고 다음을 평가한다.

```
수량별 순우위 = 해당 수량의 호가로 산출한 수렴 손익
             - 양쪽 진입·청산 수수료 - 매도세 - 금융비용 - 대차료
             - 슬리피지 - 한쪽 미체결에 대한 위험 여유
```

금융비용을 이론가격에 넣은 경우 순우위에서 중복 차감하지 않는다. 최우선 한 호가뿐
아니라 수량을 늘릴 때 소진되는 호가와 체결 가능한 정수 계약을 계산한다.
계약별 최소 순우위, 금액별 최소 순익, 자본 대비 이익, 지속시간을 함께 보고한다.
순간 기회는 신호 도착·판단·주문·체결 시각을 각각 기록해야 평가할 수 있다.

두 주문은 원자적이지 않다. 상태는 후보 → 조건 충족 → 자금/대차 확보 → 주문 전송 →
부분 체결/양쪽 체결 → 보유 → 청산 → 대사 완료로 관리한다. 브로커 요청 시간초과를
미접수로 단정해 재전송하지 않는다. 주문 ID 대사, 부분 체결 수량 헤지, 잔여 주문 취소,
한쪽 노출 한도·최대 허용시간과 비상 해소를 먼저 검증한다.
모든 신규 진입은 호가 지연·시각 불일치·연결 단절·증거금/대차 미확인 시 차단한다.
가격 차이가 장중에 곧 수렴한다는 보장은 없으며 만기 수렴 전략과 장중 평균회귀 전략의
청산 기준·자금 계획을 분리한다.

## 5. 화면 구조

| 화면 | 핵심 내용 |
|---|---|
| 시장 전체 | 기초자산별 모든 월물, 만기·승수·정상 가격 차이·유동성, 대응 현물, 감시/미감시 상태 |
| 실시간 기회 | 매수/매도 방향, 양쪽 호가·수량·시각, 비용 후 순우위, 주문 가능 규모, 제외 사유 |
| 주문·체결 | 양쪽 주문과 부분 체결, 한쪽 노출 금액·경과시간, 취소·헤지·대사 상태 |
| 포지션·증거금 | 자산별 중립화 정도, 미실현/실현 손익, 비용, 추가 증거금, 만기·청산 계획 |
| 틱 재생·전략 검증 | 기록한 실제 호가 재생, 가상 주문, 지연/미체결 스트레스, 검증 전후 비교 |
| 운용 설정 | 감시 범위·슬롯·주문 한도·최소 순우위·손실 한도·비상 중지 |

상단에는 전체 계약 수, 유효 매핑 수, 연속 감시 중인 쌍 수, 데이터 지연,
구독 예산 사용량, 신규 주문 허용 여부를 표시한다. 예시 종목과 숫자를 실시간 표에
섞지 않는다. 공통선물·현물의 사용 슬롯을 보이고 단순히 '30쌍 감시'라고 단정하지 않는다.

## 6. 서비스 역할과 검증

- value-invest: 운용 화면, 사용자 권한, 설정·감사 기록, 브로커 연결 소유자 및 주문 상태.
- 시세/신호 작업자: 브라우저 종료와 무관하게 동작. 원시 이벤트·거래소 시각·수신 시각,
  구독 공백, 재연결·스냅샷 복구를 보존하며 공유 호가장과 전략별 판단을 제공한다.
- finance-pi: 불변 호가 기록·계약 이력으로 사건 순서 재생, 동일 전략 코드의 평가,
  비용·지연·체결 모델 버전과 입력 해시를 고정한 보고서.
- common_preferred_spread/EIAYN: 종목 관계와 ETF 메타데이터. 실시간 선물 호가의 대체가 아니다.

일봉으로 순간 차익 수익률을 추정하지 않는다. 실제 관측에서 발생한 기회 수, 지속시간,
호가 잔량, 현실적인 지연 이후 가상 체결률, 순손익, 한쪽 노출, 필요한 최대 현금을
평가한다. 시간순 학습/평가 분리와 미체결·손실·데이터 공백 포함이 필수다.
호가에 보인 잔량을 모두 체결했다고 가정한 결과와 보수적 결과를 분리한다.

## 7. 순서와 완료 기준

1. 계약 자동 매핑과 시세 수집 범위 확정: 실제 마스터를 검증하고 감시 가능한 범위를 수치로 제시.
2. 양쪽 실시간 호가 수집·기록: 장중 실수신, 구독 한도, 재접속·권리조정·만기 검증.
3. 순우위 스캐너와 운용 화면: 모든 후보의 판단 근거를 원시 호가로 재현.
4. 자동 가상 주문과 finance-pi 재생: 지연·부분 체결·단절·증거금 상황을 포함한 장중 관찰.
5. 실주문 연결: 주문 상태·대사·부분 체결 복구 검증 후 사용자가 지정한 계좌·한도 안에서 활성화.

데이터가 없는 상태에서 화면만 운용 터미널처럼 바꾸거나 합성 수익을 실전 성과로
제시하지 않는다. 기존 연구 기능은 보존하되 이 문서의 실시간 시스템과 완료 상태를 분리한다.
