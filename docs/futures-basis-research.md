# 현물·선물 차익 연구

2026-09-16 · 엔진 `cash-futures-1` · `/quant` 현선물 차익 연구

## 구현 범위

finance-pi가 시나리오 생성·동시 호가 재생·회계 계산을 담당한다. value-invest는 인증,
설정 입력·사용자별 결과 보관·보고서·JSON 내보내기를 담당한다. NH 어댑터의 조회 전용
허용 목록은 변경하지 않는다. 주문 전송은 0건이며 실거래 활성화 경로가 없다.

현재 finance-pi에는 개별주식선물 월물별 동시 호가 이력이 없다. 기존 KIS 연동의 야간
지수선물과 전일 현물 종가를 결합해 실행 가능한 차익이나 과거 성과로 표시하지 않는다.
화면 기본값은 **가상 가격·비용**이다. 사용자 제공 JSON도 거래소 원본과 대조하기 전이다.

## 전략

- 현물 매수 + 고평가 선물 매도: 만기 가격 수렴과 배당 수취에서 비용을 차감한다.
- 현물 공매도 + 저평가 선물 매수: 대차 확보·수량을 요구하고 대차료와 배당 지급을 차감한다.
- 개별주식은 표준 10주 승수만 지원한다. 권리조정 계약은 중단한다.
- ETF + KOSPI200/미니 선물은 지수 금액에 맞춰 ETF 수량을 내림한다. 잔여 노출과
  추적 차이를 별도 보고한다. 동일 자산 간 무위험 차익으로 분류하지 않는다.

승수 참고: [KRX 개별주식선물](https://global.krx.co.kr/contents/GLB/02/0201/0201040401/GLB0201040401.jsp),
[KRX KOSPI200 선물](https://www.krx.co.kr/contents/OPN/01/01040201/OPN01040201.jsp),
[KRX 미니 선물](https://global.krx.co.kr/contents/GLB/02/0201/0201040204/GLB0201040204.jsp).
종목별 실제 계약 마스터·증거금·휴장일·호가단위 검증은 아직 없으며 사용자 입력을 공식 조건으로 인증하지 않는다.

## 계산과 판단

`d=+1`은 현물 매수, `d=-1`은 현물 공매도, `Q`는 주수, `N`은 계약수, `M`은 승수다.

```
순손익 = d × Q × (현물 처분가격 − 진입가격)
       − d × N × M × (선물 청산·정산가격 − 진입가격)
       + d × 배당 현금흐름 − 수수료 − 매도세 − 금융비용 − 대차료
```

실행 방향의 매수·매도 호가에 슬리피지를 적용한다. 만기 이론 우위에서 예상 왕복 비용,
기간 금융비용·대차료, 한쪽 미체결·ETF 추적 위험 공제를 뺀 값이 최소 기준을 넘어야 신호를 낸다.
다음 호가에서 조건을 다시 검증하고 자금·정수 계약·호가 수량·대차 한도의 최솟값을 체결한다.
현물과 선물 주문의 방향·수량·가상 가격은 결과 이벤트에 함께 남긴다.

한 번 진입한 계약은 목표 이익, 투자금 대비 손실 한도, 유지증거금 부족, 대차 회수,
만기 정산 또는 입력 마지막 호가에 청산한다. 청산 수량 부족·자료 단절·권리조정은
`unresolved`와 손익 null로 표시한다. 확정 가상 수익으로 만들지 않는다.
두 주문이 동시에 체결된다는 모형이며 실제 한쪽 미체결 체결기는 구현하지 않았다.
한쪽만 체결된 뒤 1% 불리하게 움직일 때의 비용 전 가격 손실 규모를 따로 제공한다.

수익률 분모는 전체 기준 투자금이다. 금융비용은 현물 전액과 개시증거금의 단리
기회비용이며 공매도 대금은 재사용하지 않고 현물 100% 담보를 추가로 가정한다.
현물 평가이익을 선물 증거금 납부 현금으로 사용할 수 있다고 가정하지 않는다.
최대 필요 자금은 개시증거금 복원 기준, 강제청산 판단은 유지증거금 기준이다.
추가 증거금 조달비용, 투자자별 소득세, 실제 결제일까지의 현금 잠김은 별도 검증 대상이다.

합성 자료는 평일 14:59 관측값으로 생성하며 휴장일 달력을 재현하지 않는다.
만기 관측은 15:40에 정산값과 현물 처분 호가가 존재한다고 가정한다. 장 마감 전의
정산값은 거절한다. 실제 현물 처분이 불가능하면 이 수렴 시나리오 손익도 실현되지 않는다.
배당 입력은 보유자가 받을 권리가 있는 세후 현금흐름이어야 하며, 공매도자는 지급액을
동일 값으로 가정한다. 실제 권리일·지급일·세금 차이는 데이터 공급 단계에서 검증해야 한다.

## 시나리오와 입력

기본 수렴, 수수료·슬리피지 2배, 배당 미수취, 중간 기초가격 30% 불리한 변동,
ETF의 불리한 추적 차이 1%를 비교한다. 경로는 결과를 설명하기 위한 가정이며
확률분포·예상 연수익·실제 백테스트로 해석하지 않는다. 스트레스마다 진입 조건도 재검증한다.

`POST /api/quant/basis/runs`: 로그인·요청 출처 검사 후 finance-pi의
`POST /api/research/basis-analysis`에 전달한다. 입력 SHA-256·결과 SHA-256·엔진·주문 0건·
손익과 마지막 원장의 일치를 검사한 뒤 사용자별 최대 50개 보고서를 저장한다.
동일 요청 키의 재전송은 기존 결과를 반환하고 다른 입력을 같은 키에 넣으면 거절한다.
`GET /api/quant/basis/runs`와 `/{id}`는 다른 사용자의 기록을 노출하지 않는다.

보고서에서 JSON 예시를 내려받아 `mode=replay`로 다시 실행할 수 있다.
필수 호가 필드: `timestamp`, `spot_at`, `future_at`(시간대 포함), 양쪽 `bid/ask`,
`spot_depth`, `future_depth`, `underlying`. 선택값은 `dividend_per_share`, `tradable`,
`corporate_action`, `borrow_available`, `settlement`다. 마지막 항목은 정산값을 실제로
알 수 있는 시각 이후여야 한다. 한 파일은 같은 계약의 순서 있는 최대 1,000개·500KB 관측이다.
현물·선물 시각 차이 2초, 관측 지연 5초가 기본 상한이다. 관측 사이 경로는 추정하지 않는다.

## 실거래 연결 전에 필요한 데이터·기능

1. 실제 계약 마스터, 월물별 호가·수량·정산가, 권리조정, 대차·계좌별 증거금 수집.
2. 원시 현물·선물의 동시 관측과 배당 권리·현금 흐름 보관. 연속선물 조정가격 사용 금지.
3. 체결 확인·중복 주문 방지·한쪽 미체결 해소·증거금 감시·비상 중지의 모의 환경 검증.
4. 실제 체결 비용을 반영한 사전 등록 전진 평가. 수익·손실·미체결 구간을 모두 보존.

기존 common_preferred_spread·EIAYN 상품 메타데이터는 관계 검토에 활용할 수 있으나,
현재 정적 상품 API를 실시간 선물 체결 데이터로 대체하지 않는다.
