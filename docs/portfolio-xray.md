# 포트폴리오 X-Ray

심층 분석 탭의 `#pfExposureWrap` 카드. 입력 없이 ETF·지주사·우선주를 풀어 본 실제 노출과 통화·자산군·업종
비중, 집중도, 위험 기여를 보여 준다. 선택 계좌(`PfStore.accountId`)를 따르고 현금은 따로 표시한다.

| 위치 | 역할 |
|---|---|
| `routes/portfolio_exposure.py` | `GET /api/portfolio/exposure[?account_id=…]` 인증 API |
| `services/portfolio/exposure.py` | 순수 계산. 수식 규약은 모듈 docstring, 손계산은 `tests/test_portfolio_exposure.py` |
| `services/portfolio/exposure_data.py` | 자료 로더(메모리 → DB → 네트워크, 실패해도 예외 없음) |
| `services/portfolio/exposure_service.py` | 조립. 사용자·계좌별 10분 캐시 |
| `services/market/sources/kind.py` | KIND 상장법인목록 provider |
| `static/js/portfolio-exposure.js` | 화면 |

## 화면 구성

위에서 아래로 한 흐름이다: 계좌·계산 시각과 데이터 기준일 칩 → 요약 띠(투자자산·현금·상위 5·HHI·모델 변동성·ETF 커버리지)
→ **구성**(자산군·통화·업종 막대) → **실제 노출**(발행사 기준 표, 순노출 칸에 막대) → **위험 기여**(왼쪽 표, 오른쪽 상관 히트맵)
→ 접어 둔 세부(ETF 풀어 보기, 지주사 풀어 보기, 계산 방식과 데이터 한계).

- 막대는 값 크기만 나타내는 한 가지 색이다. 현금·미분류 같은 분류 밖 항목은 회색, 음수는 빗금으로 구분한다.
  실제 노출 막대만 직접·선물(진한 색)과 ETF 경유(옅은 색)를 나눠 그리고, 선물 매도처럼 한쪽이 음수면 나누지 않는다.
- 히트맵의 대각선(자기 자신, 항상 1)은 색을 입히지 않는다. 양의 상관은 상승색, 음의 상관은 하락색 계열이다.
- ETF·지주사 세부는 기본으로 접혀 있고 요약 줄에 개수·커버리지·환산 합계(추정)를 먼저 보여 준다.
  데이터 기준일과 낡음 경고는 접히지 않는 맨 위에 둔다.
- 스타일은 `static/css/portfolio.css` 의 `.pf-xray-*` 다. 이 블록이 다른 카드의 `@media` 안에 들어가면 데스크톱에서
  통째로 빠진다(2026-11 머지 때 닫는 중괄호가 빠져 실제로 그랬다). `tests/test_frontend_structure_portfolio.py` 가 짝을 확인한다.

## 데이터 출처와 판단

| 항목 | 출처 | 캐시 | 낡음 기준 |
|---|---|---|---|
| ETF 구성 | eiayn `data/etfs.json` | ETag 조건부, 압축본 DB 보관, 6시간마다 확인 | 3일 |
| 지주사 지분 | holding_value `api/holdings.json` | DB 보관, 6시간 | 120일 |
| 우선주 쌍 | common_preferred_spread summary → config 폴백 | 메모리 1시간 | 7일 |
| 업종·회사명 | KIND 상장법인목록 | DB 보관, 30일 | 45일 |
| 일봉(국내) | finance-pi `/api/prices/daily` | 결과 캐시 10분 | 5일 |
| 일봉(해외·금·코인)·원화 환율 | Yahoo chart 1년 일봉(`adjclose`), 금 `GC=F`·코인 `BTC-USD` 등, 환율 `KRW=X`·달러 교차 `{통화}=X` | 메모리 3시간, 실패 시 사흘 안의 직전 값 | 5일 |
| 해외 ETF 판별 | Yahoo chart `instrumentType` | DB 보관, 90일 | - |

- **ETF는 허브가 캐시한다.** 비중 있는 구성 행이 약 5,500개(200 KB 이상)라 `summary.json` 64 KB 예산에 들어가지 않는다.
  ETag로 파일이 바뀐 때만 9 MB를 파싱하므로 요청 경로에는 영향이 없다. 재시작해도 DB 압축본을 쓴다. eiayn에 경량 파일을
  새로 발행하면 다운로드 자체를 줄일 수 있지만, 지금 이득이 작아 하지 않았다.
- **업종은 KIND를 쓴다.** KRX 업종분류는 로그인이 필요하고 DART 기업개황은 회사마다 호출해야 한다. KIND는 익명 요청 하나로 전 시장을
  받는다. 표의 열 순서가 바뀐 적이 있어(시장구분 추가) 머리글 이름으로 열을 찾는다. 해외 종목과 목록에 없는 종목은 `미분류`로 둔다.
- **해외 일봉은 원화 수익률로 바꿔 NAV 정산과 같은 시점에 맞춘다.** 심볼은 해외 시세와 같은 규칙(고정 표 → 티커 맵 →
  `yahoo_symbol`)으로 찾는다. 배당·분할 조정 종가에 그 거래소 날짜의 환율(빈 날은 5일 안의 직전 환율)을 곱하고, 국내 거래일 T의
  값으로는 T의 국내 정규장 마감(15:30) 전에 끝난 가장 최근 해외 정규장 종가를 쓴다(`services/portfolio/regular_close` 와 같은 기준).
  미국·유럽·홍콩은 전날 종가, 도쿄·시드니는 같은 날 종가가 들어간다. 같은 달력 날짜끼리 짝지으면 미국 장의 움직임이 다음 날 국내
  장에 반영되는 몫을 놓쳐 국내·해외 상관이 크게 낮아진다. 국내 일봉이 있으면 그 거래일 위에, 없으면(해외 전용 계좌) 해외 종가가
  알려진 날들 위에 마지막 값을 이어 붙인다. 열흘 넘게 묵은 시리즈는 공통 구간을 과거로 끌지 않도록 `일봉 지연`으로 뺀다.
  환율을 못 받은 종목은 원화가 아닌 수익률을 섞지 않도록 뺀다.
- **금·가상자산은 Yahoo 대용 시리즈를 쓴다.** 허브에는 KRX 금현물·업비트 일봉 이력이 없어, 자산 인사이트와 같은 심볼
  (KRX_GOLD → `GC=F`, CRYPTO_BTC·ETH·USDT → `BTC-USD`·`ETH-USD`·`USDT-USD`)을 달러로 받아 원화로 환산한다. 화면의 위험 기여
  행에 `GC=F 대용`처럼 표시한다. 달러 외 통화는 Yahoo 직접 원화 쌍 대신 달러 교차(`KRW=X ÷ {통화}=X`)를 쓴다 — `CNYKRW=X` 는
  이력이 하루치, `VNDKRW=X` 는 404 이고, 홍콩달러·엔 직접 쌍은 연초에 튀었다 돌아오는 값이 있었다.

## 한계

- **ETF**: 공개된 상위 구성만 안다. 비중이 없거나 구성이 없는 ETF는 커버리지 0%이고, 그 평가액은 `ETF 미공개 구성`으로 남긴다.
  채권·원자재형은 풀지 않고 한 줄로 둔다. HHI는 미공개분을 완전 분산으로 보는 하한이다.
- **지주사 환산은 추정치다.** 주식수는 holding_value `config.json` 설정값이고 공시와 다를 수 있다. `as_of`는 공시일이 아니라 파일을 만든
  날짜다. 지주사 평가액과 별개의 참고치라 합계·비중·HHI에 더하지 않는다. 1단계 자회사까지만 보고, 우선주는 보통주 1주와 같은 지분으로 환산한다.
- **위험 기여**: 일봉을 끝내 받지 못한 자산은 null이다(커버리지 표시). 선물은 기초자산 일봉으로 대신한다.
  금·가상자산 대용 시리즈에는 KRX 금 프리미엄·업비트 김치 프리미엄의 변동과 금 선물 월물 교체 때의 작은 가격 차가 빠진다.
  공통 구간을 절반 아래로 줄이는 신규 상장 종목은 표본 부족으로 뺀다. 현재 비중을 과거 수익률에 곱한 추정치다.
- **해외 일봉 시차**: 종가 시점을 맞춰도 국내 장의 움직임이 그날 밤 해외 장에 반영되는 몫은 남아, 국내·해외 사이 상관은 실제보다
  낮게 나올 수 있다(분산 비율이 높아 보일 수 있다). 환율은 런던 기준 일봉 종가라 해외 종가 시각과 몇 시간 어긋난다.
  국내 일봉은 finance-pi가 분할·병합만 조정한 종가라 배당락이 수익률에 섞이고, 해외는 배당까지 조정한 종가다.
- **통화**: 거래 통화 기준이라 국내 상장 해외 ETF는 원화로 잡힌다.
