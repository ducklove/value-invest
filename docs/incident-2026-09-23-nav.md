# 2026-09-23 정산 누락 복구 및 재발 방지

## 장애

9/23 20:05 정산에서 KIS 시세 요청 제한(429)이 발생했다. 한 계정은
신규 보유 한국제17호스팩(0200G0)의 시세와 이전 종목 스냅샷 모두 없어
20:07:21 정산 저장에 실패했다. 다른 계정은 성공했다. 전체 배치는
사용자 실패를 이벤트에만 기록하고 HTTP 200을 반환했다. 전체 계정의
MAX(date)를 검사하던 모니터는 부분 누락을 탐지하지 못했다.
증권사 동기화의 updated_at까지 비교하던 입력 검증은 잔고가 같아도
정산을 처음부터 재시도하여 시세 호출과 장애를 증폭했다.

## 복구

9/24 06:38 KST, 누락 계정의 9/23 정산을 복구했다. 76종목의
수량·원가는 9/24 03:30 백업과 대조했고, 20시 이후 매매·입출금·분배금·
배당 수취가 없는지 검증했다. 정상 계정에 저장된 같은 정산의 공통 종목
시세, 날짜를 검증한 국내 종가, 해외 시장의 20시 이전 분봉·종가,
가상자산 19:59분봉으로 원화 평가액을 재구성했다. USD 환율은 정상 정산에
남아 있던 값, 나머지 환율은 당시 시장 기록을 사용했으며 VND는 당시
USD/VND와 저장된 USD/KRW의 교차환율을 사용했다. 따라서 모든 종목이
당시 실패한 프로세스에서 직접 채집된 동일 틱이라고 주장하지 않는다.

복구 입력과 출처, SHA-256, 검증 결과, 원본 SQLite 온라인 백업은 운영의
`data/db-imports/nav-20260923-recovery/`에 보존한다. 개인별 잔고 자료는
Git에 넣지 않는다. `deploy/repairs/repair_2026_09_23_missing_nav.py`는 기본
읽기 검증이고, `--apply`에서 백업 후 NAV·종목·그룹·원장 정산을 한
트랜잭션으로 저장한다. 대상일/후속 정산이 있거나 잔고·원장이 바뀌면 거부한다.

## 방어 조치

- 당일 REST 시세 실패 시 날짜가 일치하는 독립 종가 소스를 조회한다.
- 자동 정산은 이전 정산 가격을 사용한 불완전 평가를 확정하지 않는다.
- 잔고 동기화 시각 변경은 재시도 원인에서 제외하되 계좌별 수량·원가·통화,
  합산 잔고, 그룹, 입출금·분배금·배당·최근 NAV 변경은 계속 검증한다.
- 자동 실행은 이미 정산된 계정을 보존하고 누락 계정만 처리한다.
  20:05, 20:15, 20:25, 20:45, 21:05, 21:35 KST 실행, API 실행 간 상호 배제.
- 사용자 실패는 error 이벤트 및 HTTP 실패로 전파하여 기존 systemd
  OnFailure 경로가 동작한다.
- 계정별 정산일을 검사하고 단 하루 누락도 error로 처리한다.
- TODAY 응답은 기대일/미완료 상태를 포함하고 카드에 `정산 미완료`를 표시한다.
- 호스트 재시작 후 아침 가격으로 새 날짜 정산을 생성하던 Persistent 실행은
  막는다. 운영시간 중 후속 시도가 누락 계정을 다시 처리한다.

외부 시세 장애 자체를 없앨 수는 없다. 이전 가격으로 성공을 가장하는
것과 계정 일부의 실패가 가려지는 것을 차단하고, 복구 경로·경보·증거를 남긴다.

배포 검증 중 추가 발견: active 타이머의 calendar를 daemon-reload하면 이전
프로세스에 예정 외 호출이 발생할 수 있었다. 해당 호출을 저장 전에 중단하고
9/24 조기 정산이 없음을 확인했다. 20시 전 기본 배치 실행을 코드에서도
차단했다(날짜를 지정한 명시적 복구는 별도). 배포 스크립트는 변경할 타이머를
먼저 중지하고, 새 앱의 healthz/readyz 검증 이후 재시작하도록 수정했다.
