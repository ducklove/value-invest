# 계좌 관리와 NH 나무 조회 연동

## 사용 방법

1. 포트폴리오 상단 **계좌 관리**에서 일반·ISA·연금 등 계좌를 만든다.
2. **이 계좌 보기**를 선택한 후 기존 잔고를 등록한다. 최초 등록·수정·등록 삭제는 현금을 변경하지 않는다.
3. 수동 매수·매도·환전·배당 수취·자금 입출금은 선택한 계좌의 해당 통화 현금에만 반영된다. 입출금 취소도 원거래의 계좌를 사용한다.
4. **전체 계좌 · 합산**에서 같은 종목의 수량과 매입원가를 합산한다. 원화와 외화로 입력된 매입가는 각각 환산한 뒤 더한다. 종목의 **계좌별 보기**에서 계좌별 보유분을 확인할 수 있다.

기존 보유 종목은 최초 실행 시 기존 계좌 또는 기본 계좌로 이전된다. 여러 계좌를 합산한 상태의 매매·수정·삭제는 계좌 선택 창으로 연결된다. 그룹·태그·목표가·메모는 종목 공통 정보다. 계좌 선택은 현재 화면에서만 유지된다.

NAV와 기간별 실적·리포트·심층 분석은 전체 포트폴리오 기준이다. 계좌별 과거 정산 기록은 아직 없으므로 개별 계좌의 요약 카드에서는 NAV·기간별 수익률·추이선을 표시하지 않는다. 현재 평가액·매입원가·종목 수익률은 선택 계좌 기준이다. 빈 계좌만 삭제할 수 있으며, 기본 계좌는 유지한다.

## NH 계좌 연결

1. 잔고가 비어 있는 계좌에서 **NH 계좌 연동**을 누른다.
2. 본인에게 발급된 **APP KEY / APP SECRET**을 입력하고 키를 확인한다.
3. 키에 연결된 계좌 목록에서 계좌를 선택한다. 본인의 계좌 선택·관리 화면에는 계좌번호 전체를 표시한다. 실계좌·모의계좌를 구분한다.
4. **계좌 종류**에서 주식·ETF / 금현물 / 국내선물·옵션 / 해외선물·옵션을 선택한다. 실제 증권사 계좌의 종류와 일치해야 한다. 주식 계좌만 해외주식 포함 여부를 선택하며, 외화 예수금은 이 선택과 관계없이 가져온다.
5. **잔고 가져오기**를 누르면 연결한다. 미리보기에서 닫으면 보유 잔고를 등록하지 않는다.

국내 주식·ETF·KRX 금현물과 미국·일본·홍콩·상해·심천 주식을 지원한다. 현금은 KRW와 기존 포트폴리오가 환산 가능한 USD·EUR·JPY·CNY·HKD·GBP·AUD·CAD·CHF·TWD·VND를 지원한다. 해외주식 조회 시장과 예수금 통화의 범위는 서로 다르다. 종목은 체결 기준 잔고를 사용한다. 원화 현금은 **D+2 예수금**, 외화는 **결제 후 예수금**을 합산한다. 현재 예수금·주문 가능액·출금 가능액은 별도 항목으로 저장하며 같은 값으로 간주하지 않는다.

국내 잔고는 NH의 상장종목 조회 옵션(`ltg_aot_dit_cd=1`)으로 비상장·상장폐지 종목을 제외한다. 종목명이나 현재가가 0이라는 이유로 제외하지 않는다. 다음 동기화가 성공하면 해당 NH 계좌에서 이전에 가져온 제외 대상 잔고도 정리되며, 수동 계좌의 보유분은 유지한다. [NH 국내 잔고 명세](https://www.nhplug.com/openapi-docs/krstock/openapi.json).

해외주식 포함을 해제해도 외화 예수금은 통화별 조회를 계속한다. 원화는 `nxt2_dd_dca`, 외화는 `stl_af_fc_dca`를 사용하며, 조회 실패나 필수 잔액 누락 시에는 일부만 반영하지 않고 기존 계좌 잔고 전체를 보존한다. [NH 통화별 예수금 명세](https://www.nhplug.com/openapi-docs/gbstock/openapi.json).

### 금현물과 선물 계좌

- 금현물은 `/krgold/inquiry/v1/goldDepositAndBalance`로 조회한다. 주식의 상장폐지 필터를 전달하지 않는다. `M04020000`은 기존 `KRX_GOLD`에 g 단위 그대로 연결하고 현금은 D+2 기준이다. [NH 금현물 명세](https://www.nhplug.com/openapi-docs/krgold/openapi.json).
- 국내선물은 `/krfuture/inquiry/v1/balance`, 한국 시간 18시~다음 날 6시에는 `/nightBalance`를 사용한다. 매수·매도, 계약 수, 평균가격, 현재가격, 평가손익을 보존한다. 같은 계약의 반대 방향도 임의로 상계하지 않는다. [NH 국내선물 명세](https://www.nhplug.com/openapi-docs/krfuture/openapi.json).
- 해외선물은 `/gbfuture/inquiry/v1/deposit`의 원화환산 합계(`TKR`)와 `/margin`의 계약별 매수·매도 잔고를 함께 조회한다. 조회 영업일은 한국 날짜로 표시하며, 합계 누락·조회 실패 시 기존 잔고를 보존한다. 계약의 원래 통화는 유지한다. 이 증거금 API에는 개별 진입단가·현재가·평가손익이 없으므로 `null`로 보존하고 화면에 **미제공**으로 표시한다. 계좌 전체 평가액·평가손익은 예수금 API 값이다. [NH 해외선물 명세](https://www.nhplug.com/openapi-docs/gbfuture/openapi.json).

선물 계약 잔고는 포트폴리오의 별도 표에서 계좌별로 보여준다. 총자산에 계약 수×가격×승수를 더하지 않는다. 국내는 `nas_tal`, 해외는 원화환산 `fdv_dsg_aet_tot_eal_amt`가 합산 기준이다. 기존 평가·NAV 경로에는 아래 원화 금액 두 항목을 넣는다.

| 합산 항목 | 잔액 | 단위 평가가격 | 평가기준 단가 |
|---|---|---|---|
| `FUTURES_BASE_KRW` 선물 평가기준액 | 계좌 평가액 − 증권사 평가손익 | 1원 | 1원 |
| `FUTURES_PNL_KRW` 선물 평가손익 | 증권사 평가손익(음수 허용) | 1원 | 0원 |

두 항목의 평가액 합계는 증권사 계좌 평가액과 같고, 평가손익 합계도 증권사 값과 일치한다. 이 행의 수량 열은 **원화 금액**이며 계약 수가 아니다. 예탁금·대용자산·계약 명목금액을 다시 현금이나 주식으로 더하지 않는다. 조회 시점의 계좌 평가이며 실시간 계약 시세나 전체 거래기간 수익률을 뜻하지 않는다. 선물 계좌가 여러 개면 이 원화 금액을 합산하며, 계약 표는 계좌별로 유지한다.

계좌 연결을 해제해도 마지막 선물 상세 스냅샷과 평가 잔고는 보존하고 자동 갱신 중단을 표시한다. 기존 연결은 주식 계좌로 유지되므로 금·선물 전용 계좌는 연결 시 해당 종류를 선택한다. 실제 증권사 주문 API는 허용하지 않는다.

홍콩 상장 위안화 거래 종목(`80000~89999.HK`, 예: `83188.HK`, `83199.HK`)의 거래 통화는 CNY다. 신규 등록과 KIS·네이버 시세 환산에 같은 구분을 적용한다. 서버 초기화 때 과거 `.HK` 일괄 추정으로 HKD가 저장된 해당 종목의 거래 통화만 CNY로 교정하며, 수량·매입가·매입가 통화·현금·과거 매매 기록은 변경하지 않는다. 실제 통화가 다른 경우의 동기화 차단은 유지하고 오류에 종목코드와 양쪽 통화를 표시한다. [홍콩거래소 코드 배정 기준](https://www.hkex.com.hk/Products/Securities/Stock-Code-Allocation-Plan?sc_lang=en).

외화 매입원가·현금·현재가의 원화 환산은 네이버 JSON 고시 환율(`api.stock.naver.com/marketindex/exchange/FX_{통화}KRW`)을 공유한다. 2026-09에 종료된 환율 HTML(HTTP 410)을 사용하지 않으며, JPY·VND의 100단위 고시를 1단위로 환산한다. 환율 조회 실패 때 이전 값은 지연값으로만 유지하고, 유효한 환율 없이 매입원가를 환산하지 않는다.

주문가능금액은 계좌에 따라 일반 항목 또는 증거금률별 20·30·40·100% 항목만 제공될 수 있어 반환된 항목을 각각 보존한다. 외화 조회의 `<원화환산합계>` 행은 통화별 현금에 다시 더하지 않는다. 연속조회는 `cts`와 `cts_flag`를 함께 전달해 마지막 페이지까지 확인한다. 필수 예수금·수량·매입가가 잘못된 경우에는 기존 잔고를 보존하고, 원본 값 없이 실패한 필드명만 서버 로그에 남긴다.

실계좌에서 초당 약 4회 조회 시 429가 재현되어, 같은 키의 조회 시작 간격은 최소 1.1초로 둔다. 429는 페이지 키를 유지한 채 최대 두 번만 대기 후 재시도하고, 계속 제한되면 부분 잔고를 적용하지 않는다. 해외 시장을 포함한 미리보기에는 보통 10초 이상 걸릴 수 있다.

NH의 `M04020000`은 기존 `KRX_GOLD`에 수량(g)·원/g 매입가를 그대로 연결한다. `RKRW221`(CMA 원화RP)은 **현금과 분리한 `CMA_RP_KRW`**로 합산한다. NH가 RP의 현재가·매입가를 0으로 반환하므로, 원 단위 평가액을 잔액으로 저장하고 단위가 1원을 적용한다. 원가는 `평가액 - 평가손익`으로 보존해 총 평가액과 손익이 NH 조회값과 일치한다. 표시된 RP 잔액은 마지막 동기화 시점 기준이며 일중 시장 시세나 즉시 출금가능액이 아니다. 다른 RP·펀드·미니금 코드를 임의로 같은 자산에 합치지는 않는다.

`MMW1003`(한국증권금융 예치)은 수시입출금 예치금으로 취급해 `CASH_KRW` 한 행에 **D+2 예수금 + MMW 평가액**을 합산한다. 원본 `nxt2_dd_dca`는 보존하고 MMW 구성액은 `balances.KRW.mmw_eal_amt`에 기록한다. 별도 종목·입출금 거래를 만들지 않으며, 반복 조회는 같은 잔고를 교체한다. 2026-09-22 운영 응답에서 MMW를 포함한 종목별 평가액 합계가 `tot_eal_amt`와 일치하고, 여기에 D+2 예수금과 외화 예수금의 원화환산 합계를 더하면 `tot_aet_amt`와 일치함을 대조했다. [NH 잔고 명세](https://www.nhplug.com/openapi-docs/krstock/openapi.json)는 예수금과 평가액을 별도 필드로 제공한다.

코드·이름이 모두 없고 체결 잔량·평가액이 모두 0인 소멸 잔고 행만 제외한다. 식별자가 없는 유효 잔고, 미지원 상품, 필수 금액 누락은 기존 잔고를 보존하며 오류로 처리한다. 잔고 오류는 계좌 동기화 상태에만 기록하고 수입·입출금 조회 오류에 복사하지 않는다.

연결 후 5분마다 잔고를 재조회하며 **잔고 동기화**로 즉시 갱신할 수 있다. 모든 페이지와 선택한 시장의 조회가 끝나야 원장을 한 번에 교체한다. 조회 실패·형식 오류·알 수 없는 종목·융자/미수/대출이 발견되면 이전 잔고를 보존하고 계좌 관리에 사유를 표시한다. 잔고 변화는 조회 결과로 반영하며 수동 매매 거래로 중복 생성하지 않는다. 증권사 주문 전송과 자동매매는 구현하지 않았다.

연동 계좌의 보유분·현금은 수동 변경할 수 없다. **연결 해제**하면 마지막 잔고가 수동 계좌로 남는다. 마지막 연결을 해제하면 그 키와 토큰도 삭제한다. 연동 중인 키의 시크릿을 변경하려면 연결을 해제하고 다시 등록한다.

## 실시간 시세

- NH 연결 사용자는 **NH 정상 체결 → KIS 보조 웹소켓 → 기존 조회 경로** 순으로 시세를 사용한다. 초기 HTTP·일괄 조회·브라우저 갱신에 같은 우선순위를 적용한다. NH 체결이 90초 이내이면 KIS와 조회 응답이 번갈아 덮어쓰지 않으며, 만료되면 보조 경로로 복귀한다. NH 값은 사용자 전용 캐시에만 저장한다.
- 국내 통합 체결 `mc`와 금현물 `g4`는 `7070`, 해외 체결 `RC`는 `7080`에 연결한다. 사용자마다 연결된 키 하나를 선택(운영 우선)하고 최대 두 소켓을 공유한다. 모의는 `17070`을 사용한다. 브라우저는 인증된 `/ws/namuh`로 전달받는다. NH 계좌 연결이 있어야 사용자 키의 시세 연결을 시작한다.
- 같은 사용자의 모든 계좌를 합쳐 국내·금현물 최대 30등록, 해외 최대 30등록으로 각각 구독한다. `NAMUH_WS_MAX_REGISTRATIONS`(1~30)로 각 소켓 한도를 낮출 수 있다. 국내에서는 금현물을 먼저 배정한다. 같은 GIC의 별칭은 한 자리만 쓰고 각 보유 코드에 전달한다.
- 금현물은 `g4 / M04020000`의 `cheprice`(원/g)를 `KRX_GOLD` 가격으로 전달한다. 전일 대비 부호·금액으로 등락률을 계산하며 거래대금은 `totvalue`(원)를 사용한다. 금 호가·예상체결가와 미니금(`M04020100`)은 이 가격에 섞지 않는다. [공식 금현물 명세](https://www.nhplug.com/openapi-docs/krgold/openapi.json).
- 금현물의 최근 90초 이내 체결값을 사용자 전용 캐시와 포트폴리오 HTTP/웹소켓 응답에 사용한다. 오래된 체결·역순 메시지는 제외한다. 연결 전·무체결·장외·장애 시에는 네이버 JSON의 `metals/M04020000`을 조회한다. 종료된 HTML 주소(HTTP 410)를 대체하며 KRX 거래소·원/g 단위를 검증하고 원본 기준시각을 보존한다. 신한은행 고시 금값·국제 금값은 섞지 않는다. 이 보조 값은 NH 실시간 체결가로 간주하지 않는다.
- 해외주식은 공식 `m_gtsstock.mst`(CP949, 164바이트)의 GIC·거래소·통화를 검증해 `RC`를 구독한다. 미국·홍콩·일본·상해·심천·호주·독일·영국의 식별 가능한 종목을 지원한다. 현지 거래일·체결시각(24시 이상 표기 포함)을 시장 시간대로 해석하고 서머타임을 적용한다. 원래 가격·통화와 체결시각을 보존하고 기존 환율 서비스로 원화 환산한다. 영국 GBp는 GBP의 1/100이다. 환율 누락·지연 체결·미래 시각·거래소 불일치는 반영하지 않는다.
- **해외 `RC`는 유료 실시간 시세 약정 고객 전용**이다. 약정이나 권한이 없으면 거절을 표시하고 기존 조회 경로를 사용한다. 소문자 `rc` 지연 체결을 실시간으로 표시하지 않는다. 개별 구독 거절은 다른 종목과 국내·금현물 소켓에 영향을 주지 않는다. [NH 해외주식 명세](https://www.nhplug.com/openapi-docs/gbstock/openapi.json), [종목마스터 구조](https://www.nhplug.com/instruments/m_gtsstock.h).
- NH 정상 체결 종목은 KIS 구독·반복 조회 대상에서 제외한다. NH 초기 연결은 30초 기다리고 미수신·한도 초과 국내 종목에 필요한 **빈 KIS 키만** 보조로 요청한다. 모든 국내 종목이 NH로 수신되면 KIS 키를 반환하고, NH 수신이 끊기면 다시 요청한다. 이 자동 보조 요청은 다른 세션을 강제로 종료하지 않는다. 관리자 수동 전환 권한과 NH 미연결 사용자의 기존 접근 규칙은 유지한다. 금·해외주식의 KIS 웹소켓은 기존에 지원하지 않으므로 해당 상품의 기존 조회 경로가 보조다.
- ACK를 받으면 ‘구독·체결 대기’, 유효한 최근 체결 메시지를 받아야 ‘실시간 시세 수신’으로 표시한다. 90초 이상 오래된 체결·미래 체결을 걸러내며 같은 NH 종목의 역순 메시지를 거부한다. 브라우저에 매초 전달하는 상태 메시지가 15초 이상 끊기면 소켓을 재연결한다. 로그아웃·재연결 이후 이전 소켓의 지연 메시지는 무시한다.
- 사용자별 NH 캐시는 분리한다. 다른 사용자의 NH 자격증명이나 시세 소켓을 공유하지 않는다. 재연결은 최대 60초까지 간격을 늘린다.
- 포털은 30등록, 공식 SDK는 실측 10등록으로 안내가 다르다. **이번 구현의 30은 설정 기본값이며 실제 키의 한도·시세 수신 검증 결과가 아니다.** [공식 공통 명세](https://www.nhplug.com/openapi-docs/common/openapi.json), [공식 SDK](https://github.com/PLUG-OpenAPI/nhplug-sdk).

## 저장과 운영

- `account_holdings`가 계좌별 잔고 원장이다. 기존 `user_portfolio`는 사용자·종목별 합산 테이블로 유지한다. 두 테이블은 같은 DB 트랜잭션에서 갱신한다.
- `broker_credentials`의 키·시크릿·토큰, `broker_account_links`의 계좌번호는 Fernet 암호문으로 저장한다. 로그인한 본인의 계좌 조회 응답에만 계좌번호 전체를 제공하며, 키·시크릿·토큰은 API 응답에 포함하지 않는다. 로그에 비밀을 출력하지 않는다. 주문 경로는 REST 어댑터 허용 목록에 없다.
- `BROKER_ENCRYPTION_KEY`가 있으면 이를 사용한다. 그렇지 않으면 `BROKER_KEY_FILE` 또는 DB 디렉터리의 `.broker-encryption.key`를 사용하며 최초 등록 때 0600 권한으로 생성한다.
- **암호화 키를 DB와 분리하여 안전한 곳에 백업해야 한다.** 기존 DB 백업만 복구하면 NH 암호문을 해독할 수 없다. `.broker-encryption.key`는 Git 제외 대상이며 배포 중 삭제하거나 새 키로 덮어쓰면 안 된다. 키를 잃으면 사용자에게 키를 다시 등록받아야 한다.
- `finance-pi` 환경의 공유 키나 `NAMUH_ACCOUNT_ID`를 특정 사용자 계좌에 자동 연결하지 않는다. 계좌 관리에서 등록한 사용자 키와 그 키의 계좌목록으로 소유 범위를 확인한다.
- DB 변경은 테이블·컬럼 추가 방식이다. **계좌 원장 도입 전 버전으로 롤백해 잔고를 수정한 경우에는 재배포 전에 백업 복구 또는 원장 대조가 필요하다.** 이전 코드는 합산 테이블만 쓰므로 원장을 자동으로 다시 덮어쓰지 않는다.

검증: 계좌 합산·소유권·계좌별 현금·재시도 중복 방지·입출금 취소·DB 롤백·암호문·토큰 재사용·NH 응답 파싱·틱 신선도 테스트와 브라우저 등록/취소/연결 시나리오를 제공한다. NH 외부 응답은 테스트에서 대체하며, 실제 사용에는 발급 키의 인증·권한·잔고·장중 틱 수신 확인이 추가로 필요하다.
