# 기존 배당 수취 기록과 분배금 출금

수동 배당 수취 입력 기능은 종료했다. 캘린더의 수취 입력 버튼, 보유종목 상단의 배당금 수취 버튼, 입력창과 클라이언트 스크립트를 제거했다. 저장·미리보기·입력 후보 API도 제공하지 않는다. 기존 배당 기록은 조회·누계·수익 정산과 NH 입금 중복 집계 방지에 계속 사용한다.

## NH 배당 자동 반영과 기존 기록

NH 연결 계좌의 국내·해외 배당 입금은 [NH 수입·입출금](namuh-account-activity.md#배당-자동-반영-배당-전용-경로)에서 자동으로 가져온다. 현금은 NH 잔고 동기화로 반영하고 수익 분해에 배당 수입으로 분류한다.

[배당 캘린더](dividend-calendar.md)는 NH 입금을 배당 일정에 연결해 실제 수령일에 NH 배지를 붙이고, 계좌 수령액은 배지 툴팁으로 표시한다. 표의 총액·세금·실 수령액은 주당액과 수량으로 계산한 금액이다.

기존 수취 기록은 같은 계좌·종목·통화, 수취일 ±5일과 실수령액이 맞는 NH 기록에 연결한다. 연결된 배당은 수익 분해에서 한 번만 집계한다. 기존 원장과 일별 NAV 정산 내역은 유지한다.

## 분배금 출금

상단의 **분배금 출금**에서 기존 수취 기록의 통화별 세후 누계·이미 분배한 금액·미분배액을 확인한다. 미분배액이 기본 출금액이다. 실제 현금과 미분배액을 초과할 수 없다. 이미 NAV 좌수가 정산된 포트폴리오에서 사용할 수 있다.

분배 시 현금과 실제 NAV가 감소하며 좌수는 유지된다. 분배금은 일반 출금·환매와 구별되며 `portfolio_cashflows`에 일반 출금으로 저장하지 않는다. 기존 자금 흐름 표에는 **분배금 / 좌수 유지**로 함께 표시한다.

차트·기간 실적·리스크·기기 요약은 분배금을 재투자한 총수익 기준가를 사용한다. 실제 NAV는 차트 아래 별도로 표시한다. 일별 정산에서 좌당 분배금 `distribution_per_unit`과 누적 `return_factor`를 저장하며 `return_nav = nav × return_factor`다. 같은 날 추가 정산도 새 분배만 반영한다. 외부 입출금의 좌수 정산은 기존 방식대로 유지한다.

## API와 저장 계약

- `/api/portfolio/dividend-receipts`: GET 기존 내역, `/totals`: GET 기존 누계. POST 저장과 `/preview`·`/candidates`는 제거했다.
- `/api/portfolio/distributions`: GET 내역, POST 분배 저장. `/preview`는 미리보기, `/balances`는 통화별 수취·분배·미분배 누계다.
- 분배는 현금·`portfolio_distributions`를 같은 트랜잭션으로 저장한다. NAV 정산 시 적용 날짜와 스냅샷·수익 계수를 함께 저장한다.
- `(google_sub, request_id)`로 응답 유실·중복 클릭·재시도를 한 번만 반영한다. 미리보기 이후 잔고·누계·정산 상태가 바뀌면 409로 재확인을 요구한다.
- 금액은 서버에서 Decimal로 계산하며 현재 잔고에 반영한다. 소급 NAV를 다시 작성하지 않는다.
- 기존 수취·분배 원장 취소와 과거 NAV 재작성은 제공하지 않는다.

분배 화면은 `portfolio-distributions.js`를 지연 로드한다. 기존 원장의 조회·수익 분해·NAV 정산 테스트와 분배의 잔고 검증·응답 유실 재시도 테스트를 유지하고, 수동 수취 API가 차단되는지 검증한다.
