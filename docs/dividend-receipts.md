# 배당금 수취와 분배금 출금

보유종목 상단의 **배당금 수취**에서 실제 받은 배당을 기록한다. 심층 분석의 배당 캘린더에서도 **수취 입력**으로 해당 스케줄을 바로 불러올 수 있다.

- 배당 스케줄에서 종목·통화·주당 배당금·보유 수량을 채운다. 지난 일정은 [기준 시점 보유](dividend-calendar.md#기준-시점-보유) 수량(장 마감 정산 기록, 전 계좌 합산 — 첫 기록 이전은 첫 기록으로 추정), 미래·예상 일정은 현재 보유 수량이다. 계좌별 실제 배당 대상 수량으로 수정할 수 있다. 기준 시점에 보유하지 않은 배당은 후보에 없고, 지금은 판 종목도 그때 보유했으면 후보에 있다.
- 캘린더는 [종목별 배당 일정](dividend-calendar.md)의 공시 지급일과 배당락·기준일을 구분한다. 실제 공시·수집 이력만 수취 입력에 연결하며 예상 건은 공시 후 연결된다. 과거 공시 지급일은 수취일에 채우지만, 미래일·배당락일·기준일은 넣지 않는다. 증권사의 실제 입금일과 금액을 확인한 후 저장한다. 스케줄 선택만으로 현금을 변경하지 않는다.
- 보유 목록에 없는 종목도 코드·이름을 직접 입력한다. 입력 방식은 **주당 배당금 × 수량** 또는 **세전 총액**이다.
- 원천징수 기본값은 국내 15.4%, 미국 15%, 중국 14.4%, 홍콩 15.4%다. 사용자가 요청한 일반 계좌 입력 기본값이며, 국가·발행사·계좌별 과세를 판정하는 세금 계산기는 아니다. 국가·세율·실제 공제액을 바꿀 수 있고, 공제액 직접 입력이 세율 계산보다 우선한다.
- 원천징수 자동 금액은 해당 통화의 최소 단위 미만을 버린다. 증권사의 세목별 반올림·환전 정산 차이는 실제 공제액으로 수정한다.
- 외화 수취는 같은 통화의 현금에 더한다. 원화 수익 분류에 필요한 수취 환율은 스케줄의 참고 환율 또는 보유한 USD 참고 환율로 채울 수 있다. 실제 수취 환율을 확인하며, 환전 자체는 실행하지 않는다.

## NH 배당 자동 반영과 미확인 태그

NH 연결 계좌의 국내·해외 배당 입금은 [NH 수입·입출금](namuh-account-activity.md#배당-자동-반영-배당-전용-경로)에서 자동으로 가져온다.
현금은 NH 잔고 동기화가 이미 반영하므로 이 화면의 수취 기록 없이도 수익 분해에 배당 수입으로 나타난다.
NH 계좌의 배당을 이 화면에서 다시 수취하면 현금이 이중으로 늘 수 있다.

- 수취 내역의 각 기록은 같은 계좌·종목·통화, 수취일 ±5일, 실수령액(반올림 허용)이 맞는 NH 배당 입금이 있으면 **NH 확인**, 없으면 **미확인**이다.
  NH 확인 수취와 짝지어진 NH 배당은 수익 분해에서 한 번만 집계한다(수동 수취가 이미 분류).
- 배당 캘린더는 NH 배당 입금을 일정에 연결한다([연결 규칙](dividend-calendar.md#nh-배당-입금-연결)).
  지급일은 입금이 지급일 −3일~+10일(당일·이른 입금 포함, 더 늦으면 다음 일정 전까지), 배당락·기준일(해외 Yahoo 이력 포함)은
  권리일 −1일부터 해외는 다음 권리일 전(없으면 +60일), 국내는 +130일 안에서 종목별 순서대로 배정되면 **NH 확인**이고
  실제 입금일·세후 금액·세금 정산을 보여 준다. 같은 날 같은 종목 입금 여러 건은 한 일정에 합계로 붙는다.
  지난 지급일에 입금이 없으면 **미확인**이다. 배당락·기준일은 NH 계좌에만 보유한 종목이 대기 기간을 넘겼을 때만 미확인이다.
  미확인은 실제로 받지 못했거나 NH 외 계좌·종목코드 차이로 대조되지 않은 경우다.
- 어느 일정에도 연결되지 않은 NH 입금(미보유 종목 등)은 **NH 입금** 행으로 실제 금액을 보여 준다. 수취 대상이 아니다.
- NH 입금으로 확인된 일정은 수취 입력 목록에서 선택할 수 없다(`· NH 입금 확인`). 입금이 없는 미래·예상 일정은 판정하지 않는다.
- NH 입금 세전 합계가 기준 시점 수량 × 주당 배당보다 뚜렷이 적으면(그 시점 수량이 확실할 때) NH 몫만 확인한 것이므로 **NH 일부 확인**이고, 나머지 몫의 수취 입력은 그대로 둔다. 금액을 비교할 수 없으면 같은 종목을 지금 NH 밖 계좌에도 보유하는지로 정한다([판정](dividend-calendar.md#nh-배당-입금-연결)).
- NH 연동 계좌에만 있는 종목(국내·해외)의 배당을 같은 종목·통화 NH 입금(실거래일·처리일) ±10일 안에 수동 수취로 기록하면
  서버가 거절한다(현금 중복 방지). 배당락·기준일 일정에서 고른 수취는 그 권리일 −1일 이후 첫 NH 입금이 해외 +35일,
  국내(원화) +130일(결산배당 4월 지급 — 캘린더 연결 범위와 같다) 안이면 같은 회차로 보고 거절한다.
- 판정은 조회 시 계산하며 저장된 수취·현금·NAV를 바꾸지 않는다.

## 분배금 출금

상단의 **분배금 출금** 또는 수취 창의 **누적 배당금 분배하기**에서 통화별 세후 수취 누계·이미 분배한 금액·미분배액을 확인한다. 미분배액이 기본 출금액이다. 실제 현금과 미분배액을 초과할 수 없다. 이미 NAV 좌수가 정산된 포트폴리오에서 사용할 수 있다.

수취 시 현금이 증가하고 배당 수익으로 분류된다. 분배 시 현금과 실제 NAV가 감소하며 좌수는 유지된다. 분배금은 일반 출금·환매와 구별되며 `portfolio_cashflows`에 일반 출금으로 저장하지 않는다. 기존 자금 흐름 표에는 **분배금 / 좌수 유지**로 함께 표시한다.

차트·기간 실적·리스크·기기 요약은 분배금을 재투자한 총수익 기준가를 사용한다. 실제 NAV는 차트 아래 별도로 표시한다. 일별 정산에서 좌당 분배금 `distribution_per_unit`과 누적 `return_factor`를 저장하며 `return_nav = nav × return_factor`다. 같은 날 추가 정산도 새 분배만 반영한다. 외부 입출금의 좌수 정산은 기존 방식대로 유지한다. 분배금은 일별 정산 기준으로 재투자한 것으로 계산하므로 장중 지급시각의 재투자 성과와는 차이가 있을 수 있다.

예: NAV 1,100, 10좌인 포트폴리오에서 세후 배당 846원을 받으면 NAV는 1,184.6이다. 846원을 분배하면 실제 NAV는 다시 1,100, 좌수는 10이며 총수익 기준가는 1,184.6으로 유지된다.

## 저장 계약

- `/api/portfolio/dividend-receipts`: GET 내역(`verification`: `nh_confirmed`|`unconfirmed`, `nh_match`), POST 수취 저장. `/preview`는 미리보기, `/candidates`는 최근 12개월과 향후 3개월 스케줄(기준 시점 보유분만, NH 입금 행 제외, `verification`·`paid_date`·`shares`·`holding_basis` 포함), `/totals`는 수취 누계다.
- `/api/portfolio/distributions`: GET 내역, POST 분배 저장. `/preview`는 미리보기, `/balances`는 통화별 수취·분배·미분배 누계다.
- 수취는 현금·`portfolio_income_events`의 세후 배당 분류·`portfolio_dividend_receipts` 원장을 하나의 `transaction()`에 저장한다. 분류를 따로 지워 원장과 달라지지 않도록 보호한다.
- 분배는 현금·`portfolio_distributions`를 같은 트랜잭션으로 저장한다. NAV 정산 시 적용 날짜와 스냅샷·수익 계수를 함께 저장한다.
- `(google_sub, request_id)`로 응답 유실·중복 클릭·재시도를 한 번만 반영한다. 수취 스케줄은 `(google_sub, source_key)`도 유일하므로 재입력을 막는다. 미리보기 이후 잔고·누계·정산 상태가 바뀌면 409로 재확인을 요구한다.
- 모든 금액은 서버에서 Decimal로 계산하고 기존 REAL 잔고의 저장 정밀도를 초과하면 차단한다. 현재 잔고에 반영하며 소급 NAV를 다시 작성하지 않는다. 과거 실제 수취일과 별개로 수익 분류는 현금이 반영된 최초 NAV 정산일에 귀속한다. 정산 전에는 기록일에 잠정 표시하고, 정산된 기간 손익에는 아직 포함하지 않는다.
- 이 화면에서 이미 현금에 반영한 배당을 다시 기록하면 이중 입금된다. 기존 ‘배당·비용 분류’는 이미 반영한 현금을 분류하는 용도로 유지한다.
- 수취·분배 원장 취소와 과거 NAV 재작성은 제공하지 않는다. 분배 정산이 있는 계정의 기존 좌수 전용 복구 스크립트는 수익 계수를 손상하지 않도록 변경 적용을 차단한다.

화면은 `portfolio-dividend-receipts.js`와 `portfolio-distributions.js`를 각각 지연 로드한다. 테스트는 국가별 세율, 세액 직접 입력, 현재/배당 대상 수량, 미래 수취 차단, 원자적 롤백, 사용자 격리, 스케줄 중복, 미분배 한도, 외화 현금, 응답 유실 재시도, NAV·총수익 정산과 브라우저 저장을 검증한다.
