# 연동 계좌 예수금 변동 사유

실계좌 잔고 동기화가 성공하면 계좌·통화별 현금의 직전 조회 대비 순변동을 별도 원장에 남긴다.
최초 추적·연결·재연결 잔고는 기준 잔고이며 질문하지 않는다. 서버가 브라우저 접속과 무관하게
추적하므로 다음 로그인 때 미입력 내역을 자동 표시한다. 계좌 관리의 **예수금 변동 사유·이력**에서
다시 열거나 기존 사유를 수정할 수 있다. **나중에 입력**으로 닫으면 알림 버튼을 유지한다.

## 자동 대조

확정된 증권사 원장의 배당·분배금, 이자, 대여료, 양도소득세, 매매 결제, 계좌 내 이동 및
관리 상대계좌가 명시된 이체를 같은 날짜·통화의 관측액과 대조한다. 추적 시작 잔고에 이미
포함된 원장은 제외하며, 대조한 금액을 다음 변동에 재사용하지 않는다. 해외 배당의 원화
추가 원천세도 원화 변동에서 별도로 대조한다. 지연 수집된 수입과 원본 정정도 매 동기화마다
다시 대조하며 설명 대상액이 바뀌면 수정 버전을 올린다. 이전에 입력한 사유는 변경 이력에 보존한다.

NH의 원화 예탁금이용료·예수금이자·예탁금이자·이자입금·이자지급과 대여료는 종합거래내역의
명시적 적요와 금액으로 일별 합계를 추가 대조한다. 세전 거래금액에서 세금·수수료를 뺀 금액을
사용하며, 앞 행의 원화 예수금이 있으면 실제 차이와 검산한다. 필드 누락·불일치가 있으면 그날
해당 분류 전체를 보류한다. RP 상환, 원금 혼합, 취소·정정, 외화 수입은 이 경로에서 추정하지 않는다.
거래번호 없는 수입에 가짜 거래번호를 부여하지 않으며, **사유 대조용 일별 합계**로만 저장한다.
기간 재조회는 합계를 교체하고 잔고·수익·NAV 원장에는 가산하지 않는다. 배당 수집은 기존과 같다.
이자 금액이 소액 기준보다 커도 API 금액으로 설명되면 사유를 요구하지 않는다.

현금 합산 대상 `MMW1003`의 `MMW매도`는 별도로 검산한다. 운영 응답의
`거래금액 − 거래수량(원금) = 이자금액` 관계와 세금·수수료·매도 후 잔량 0을 확인하고,
앞 행의 원화 예수금이 있으면 매도 세후 금액과 실제 예수금 증가도 비교한다.
원금을 제외한 평가이자(`mmw_interest`)와 나중에 빠지는 세금·수수료(`mmw_charges`)를
각각 양수·음수의 대조 자료로 저장한다. 이자는 이미 합산 MMW 평가액에 반영돼 있어
현금·수입·NAV에 다시 더하지 않는다. 다른 RP·CMA 상품이나 취소·부분 매도에는 적용하지 않는다.
같은 날 여러 변동이 있을 때는 금액이 정확히 맞는 관측을 먼저 사용해 대여료를 다른 수입에서
성급하게 차감하지 않는다. 전체 확인 금액과 한 구간의 순변동이 일치하면 그 구간에서 대조한다.

세금·계좌 간 이체와 다른 증권사의 매매·환전은 확정 원장이 없으면 종류를 자동 확정할 수 없다.
같은 금액의 반대 방향 변동만으로 관리 계좌 간 이체를
단정하지 않는다. 관측액보다 큰 수입을 임의로 분할해 제외하지 않는다.

## 소액 자동처리

API로 설명되지 않는 변동도 중요도 기준 이하이면 입력 창·미입력 알림에서 제외한다.
거래 종류를 이자로 추정하지 않고 전체 이력에 **소액 자동처리**로 남기며 사용자가 원하면
직접 사유를 기록할 수 있다. 이미 쌓인 미입력 내역에도 조회 즉시 적용한다.

- 기준은 `min(10,000원, max(1,000원, 해당 통화 예수금 × 0.01%))`이다.
- 예수금은 변동 전후 절댓값 중 큰 값이다. 계좌·연결·통화·날짜별 미확인 **절대금액 합계**로
  판단하며 여러 관측의 기준이 다르면 가장 작은 기준을 적용한다. 입출금 상쇄로 합계를 줄이지 않는다.
- 누적액이 기준을 넘으면 해당 날짜의 미입력 항목이 다시 확인 대상으로 나타난다.
  API로 설명됐거나 사용자가 이미 사유를 입력한 금액은 미확인 누적액에서 제외한다.
- 외화는 신선한 환율 캐시로 원화 기준을 원통화에 환산한다. 관측 때 계산된 기준을 보존하므로
  나중에 캐시가 없어져도 처리가 바뀌지 않는다. 추가 환율 HTTP 요청은 만들지 않는다.
  환율을 확인할 수 없는 외화는 원화와 같은 숫자로 취급하지 않고 소액 자동처리를 보류한다.
- 기존 자료는 마지막 저장 예수금에서 관측된 **원래 순변동**을 역순으로 빼 당시 예수금을
  복원하고 같은 비율 기준을 적용한다. 미설명 금액으로 역산하거나 현재 잔고를 과거에 그대로
  적용하지 않는다. 연결 지문·추적 시작일·마지막 관측 시각과 저장된 잔고 기준이 맞지 않아
  복원할 수 없는 자료만 기본 1,000원 기준으로 남긴다. 조회 중 원본 기록은 수정하지 않는다.

사유 요구 여부만 바꾸며 현금·손익·좌수는 변경하지 않는다.

이 원장은 **개별 거래가 아닌 조회 구간의 순변동**이다. 여러 거래는 합쳐지며, 구간 내 입금과
출금이 완전히 상쇄되면 잔고 조회만으로 검출할 수 없다. 보유 수량·매입가도 변하면 매매·입출고·
CMA 이동 확인 안내를 표시한다. 선물 계좌의 합성 CASH 평가액과 모의계좌는 추적에서 제외한다.

## 사유

- 비관리 계좌 입금·출금, 배당·분배금 출금, 생활비·소비, 증여·지원금, 대출·상환,
  세금·수수료, 정정·환급·취소, 일반 입출금, 기타.
- 자동 대조 자료가 없을 때 직접 확인할 수 있는 관리 계좌 간 이체, 배당·분배금 입금,
  대여수수료 입금, 이자 입금, 양도소득세 출금, 매매 결제, 환전, CMA·RP 이동.

입금·출금 방향에 맞는 항목만 선택한다. 일반 입출금·기타는 상세 사유가 필수이며,
여러 사유가 섞인 경우 금액별 내용을 상세 사유에 기록한다.

사유 저장은 기록만 변경한다. 현금은 이미 증권사 잔고에 반영되어 있으므로 다시 더하거나
빼지 않으며, 이 화면에서 NAV 좌수 발행·분배금 원장을 생성하지 않는다. 성과 원장은 기존
확정 증권사 거래내역 경로를 따른다. 외화는 원통화로 기록하고 환율을 추정하지 않는다.

## API·저장

- `GET /api/portfolio/cash-reviews?pending=true&offset=0`: 연결된 계좌의 미입력 100건과 총 건수.
- `pending=false`: 자동 확인·사유 입력·연결 해제한 과거 내역까지 조회.
- `PATCH /api/portfolio/cash-reviews/{id}`: `revision`, `category`, `reason` 저장.

`broker_cash_review_state`는 계좌 연결 지문·기준 원장·마지막 현금을,
`broker_cash_reviews`는 관측 구간·순변동·설명 대상액·사유·버전을 보존한다.
`broker_cash_review_notes`에는 사유 수정 이력을 남긴다. 잔고 교체와 관측을 한 트랜잭션에서
커밋하고 후속 검증 실패 시 함께 롤백한다. 사용자별 조회·저장과 오래된 버전의 저장 거절을 적용한다.
프런트엔드는 다른 행의 초안과 저장 실패한 입력을 보존하며 로그아웃 뒤 늦은 응답은 폐기한다.

`broker_cash_review_evidence`는 NH 수입의 조회 기간·날짜·통화·분류별 합계를 저장한다.
확정 거래 원장과 같은 날짜·분류의 수입이 있으면 중복 사용하지 않는다.
API 항목의 `auto_resolution`은 `confirmed`(거래내역 확인), `minor`(소액 자동처리), `null`이며,
`review_required`와 원통화 `minor_limit`을 함께 반환한다.

공식 명세 확인: [NH 공통 API](https://www.nhplug.com/openapi-docs/common/openapi.json), 2026-10-22.
`totalTransaction`의 `sps_cd_krl_anm`, `trd_amt`, `int_amt`, `tax_sum`, `trd_orn_fee`, `trd_af_dca`를 사용한다.
