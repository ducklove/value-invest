# 정규장 종가 기준 일정산

국내 정규장 종가로 공식 일간 성과를 확정한다. 현재가와 총평가액은 계속 최신
시세를 표시한다. 포트폴리오 Today 카드는 하루 종일(금일 정산이 생긴 15:35~24:00
포함) **전날 정산 대비 최신 평가**를 보여 준다. 금일 정산은 NAV 좌수와 다음 날의
Today 기준으로 쓰인다(2026-09-30 변경). 저녁 브리핑 이후 현재가를
정규장 종가로 되돌리는 작업은 없다.

## 가격과 잔고 기준

- 기준 시각은 KST 15:30, 첫 계산은 15:35다. 보유 수량·현금·입출금·분배금은
  앱 DB에 15:30까지 반영된 상태를 변경 이력에서 읽는다. 장후 매매·입출금은
  다음 정산에 반영한다. 증권사에서 체결됐더라도 앱에 늦게 동기화된 거래는
  이 시각의 이력에 없다. 증권사 체결 원장 자체를 소급 복원하는 기능은 아니다.
- 국내 주식은 KIS `market=J`를 명시해 마감 후 10분 이내 최초 성공 가격을
  보존한다. 기존 일봉 API는 장후 값으로 갱신되므로 정규장 종가 대용으로 쓰지 않는다.
- 해외 주식은 기준 시각까지 끝난 현지 정규장 일봉의 비조정 종가를 사용한다.
  진행 중인 세션은 제외한다. 가격의 현지 거래일도 저장한다.
- 환율·24시간 자산은 마감 후 수집 창의 관측값이다. 실제 수집 시각을 저장하며
  정확히 15:30 체결가라고 표현하지 않는다. 해외 주식은 이 환율로 원화 환산한다.
  USD 표시 성과도 양일의 보존 환율을 사용한다. 표시용 환율이 없으면 해당
  달러 성과는 비워 두며 최신 환율로 확정값을 바꾸지 않는다.
- 한 종목이라도 가격·환율이 빠지면 전체 정산을 확정하지 않는다. 시세 확보와
  NAV 저장은 분리하며, 재시도는 이미 확보한 가격을 재사용한다. 수집 창을 놓친
  종목은 늦은 현재가나 전일 값으로 채우지 않는다.
- NAV·종목 및 그룹 스냅샷·입출금 좌수·배당 귀속은 한 트랜잭션으로 저장한다.
  확정 후 반복 실행은 가격이나 NAV를 변경하지 않는다.

`settlement_versions`는 앱에 입력된 변경 시각과 내용을 보존한다.
`settlement_price_inputs`는 가격·환율·출처·수집 시각을 보존한다.
`portfolio_snapshots.price_basis=regular_close_v1`로 새 기준을 구분한다.

## 정기 작업과 브리핑

| 작업 | 기본 KST 시각 | 내용 |
| --- | --- | --- |
| 일정산 | 15:35, 15:37, 15:39 | 15:30 잔고와 정규장 가격으로 확정 |
| 저장 재시도 | 15:45, 15:55 | 이미 확보한 입력만 사용 |
| 클로징 브리핑 | 15:45 | 확정 일간 성과·기여 종목, 국내 지수·수급 |
| 장후 관측 | 20:05, 20:10 | 정규장 대비 국내 장후 가격 변화 별도 저장 |
| 나이트 브리핑 | 20:40 | 장후 변화·공시·야간 변수 |
| 모닝 평가 / 브리핑 | 07:00 / 07:30 | 완료된 해외 정규장과 환율을 반영한 평가·해외시장 |

오후 정산이 없으면 클로징 브리핑을 발송하지 않고 배치를 실패 처리한다.
저녁 장후 자료가 없으면 미수집을 표시한다. 장후 기여 금액은 정규장과 장후의
보유 수량이 같은 종목만 계산하며, 실제 매매손익을 의미하지 않는다.

달력은 `domain/market_calendar.py`를 공유한다. 수능일은 거래시간 공지 확인 후
`.env`의 `PORTFOLIO_MARKET_SESSIONS`에 날짜별 마감 시간을 넣어야 한다.
16:30 마감용 16:35~16:45 정산 재시도와 16:45 브리핑 타이머도 설치된다.
정상일의 16:45 브리핑은 건너뛴다. 그 외 임시 시각은 타이머도 함께 조정한다.
새 연도 달력은 사전 검토 후 추가해야 한다.

## 과거 자료와 전환

기존 이력은 `legacy_latest`로 보존한다. 과거 마감 잔고와 검증된 가격이 모두
없으면 재계산하지 않는다. 새 기준의 첫 날은 NAV 1,000으로 별도 구간을 시작하며
저장 행에는 전환 차이를 당일 손익으로 기록하지 않는다. 정규장 확정 일간 성과
(`regular_performance` — 클로징 브리핑·전자잉크 일간)는 첫 날에도 아래 연결
규칙으로 직전 구간 마지막 정산과 비교해 연결 이력과 같은 전환일 수익률을 낸다
(연결할 수 없을 때만 비교 없음).

조회 시에는 두 구간을 **체인 링크**해 전체 이력을 하나의 NAV 척도로 보여 준다
(`services/portfolio/nav_link.py`, 저장 행은 바꾸지 않음). 기준이 바뀌는 경계마다
이전 구간 마지막 정산 d0, 새 구간 첫 정산 d1에 대해

- 전환일 수익률 `r = (V(d1) − 순입출금) / V(d0) − 1` — 순입출금은 d0 정산 이후
  d1 정산까지 반영된 입금(+)·출금(−)·분배금(−)으로 Today 카드와 같은 정의다.
- 연결 배수 `k = RN(d1) / (RN(d0) × (1 + r))`, `RN = return_nav = nav × return_factor`.

이전 구간의 NAV 계열 값(`nav`, `return_nav`, `distribution_per_unit`)에 `k`를
곱한다. 경계가 여럿이면 뒤에서부터 곱한다. 평가액·투자금·좌수 같은 금액 값은
그대로라, 연결된 행에서 `nav × total_units`는 평가액과 다르다. 연결된 행에는
`linked=true`, `nav_link_factor`, `raw_nav`(저장 값)가 붙는다. 평가액이 없거나
0이라 연결할 수 없는 경계가 있으면 그 이전 행은 숨기고 경고 로그를 남긴다.

- `/api/portfolio/nav-history`(기본): 연결된 전체 이력. 심층 분석·추이 차트·
  위험 지표·기간 실적/보고서·AI 분석이 이 값을 쓴다.
- `/api/portfolio/nav-history?include_legacy=true`: 연결하지 않은 저장 원자료
  전체(감사용). 구간마다 NAV 척도가 다르다.
- MTD/YTD 기준점(`month-end-value`/`year-start-value`, 전자잉크 YTD)도 기준점
  뒤에 경계가 있으면 NAV만 같은 방식으로 연결해 비교한다. 금액 손익은 원래
  평가액 기준이다. 연결할 수 없을 때만 `comparison_unavailable`을 돌려준다.
- `/api/portfolio/cashflows`(심층 분석 입출금 표의 '당시 NAV'): 발행 NAV
  `nav_at_time`도 반영 정산일(`applied_snapshot_date`, 없으면 `date`)이 속한 구간의
  누적 `k`를 곱해 연결 이력과 같은 척도로 보여 준다. 좌수(`units_change`)는 실제
  값이라 그대로다. 연결된 행에는 `raw_nav_at_time`(저장 값)·`nav_link_factor`가
  붙고, 연결할 수 없는 구간의 행은 `nav_at_time=null`, `nav_link_unavailable=true`.

예: 2026-09-29 `legacy_latest` 평가액 6,693,228,966원(NAV 986.48) → 2026-09-30
`regular_close_v1` 6,669,406,885원(NAV 1,000), 그 사이 입출금이 없으면
`r ≈ −0.356%`, `k ≈ 1.01733`이라 연결된 9/29 NAV는 약 1,003.57이다.

배포 이전의 잔고 변경 이력은 생성할 수 없다. 첫 배포는 마감 전에 앱을 시작해
기초 이력을 남겨야 한다. 마감 후 처음 설치했다면 다음 거래일부터 새 기준 정산이
가능하다. 현재 잔고를 과거 잔고로 소급해서 쓰지 않는다.

보존 자료가 있는 기간을 다시 계산할 때는 아래 도구를 사용한다.

```bash
.venv/bin/python scripts/rebuild_regular_close_history.py --db /path/to/cache.db --start YYYY-MM-DD
.venv/bin/python scripts/rebuild_regular_close_history.py --db /path/to/cache.db --start YYYY-MM-DD --apply
```

첫 명령은 원본 온라인 백업 후 복사본에서만 계산한다. DB 옆
`.deploy-repairs/regular-close-*/report.json`에서 날짜별 전후 값과 복원 불가 사유를
검토한다. 적용 명령도 다시 점검하며, 한 날짜라도 자료가 없거나 점검 중 원본이
바뀌면 중단한다. 적용 시 이후 정산을 시간순으로 재계산하고 저장된 기간 보고서를
갱신한다. 최신 잔고·시세 캐시는 변경하지 않는다. 자료가 없는 이전 기간을
복원하려면 당시 잔고·정규장 가격의 별도 확보와 검증이 먼저 필요하다.

## 배포 후 확인

1. 정규장 마감 전 새 앱을 시작해 변경 이력 수집 시작 시각을 확인한다.
2. `portfolio-snapshot.timer`, `portfolio-after-close.timer`, 세 브리핑 타이머의
   활성화 상태와 다음 실행 시각을 확인한다. 배포 스크립트가 새 유닛을 설치한다.
3. 최초 정산에서 가격 출처·수집 시각, 15:30 수량·현금, NAV와 종목 합계를 확인한다.
4. 장후 가격·입출금 변경 후에도 확정 일간 성과가 유지되는지 확인한다.
5. 품질 점검과 `journalctl -u portfolio-snapshot.service`로 누락을 확인한다.
   실패한 날짜를 현재가로 임의 보정하지 않는다.
